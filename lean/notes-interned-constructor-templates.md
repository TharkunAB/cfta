# Constructor templates through separate interned caches

`InternedConstructorTemplates` derives stable requests from finite template
syntax. It does not require a caller to supply a stable family of arbitrary
cache computations.

The supported template constructors are the local argument, an immutable
captured node, an ordinary node with ordered edge templates, and a union.
The template can contain these constructors recursively. An enclosing Mu
uses the template for both probes and for its actual-identity body. Generated
nested Mu templates are not included. Previously constructed Mu nodes can
occur as captured values.

## Exact constructor operations

`EdgeKey` retains the symbol, ordered child references, and complete constraint
parameter. `makeEdge` models the source's direct edge-interning path.
For substitution, `setChildren` uses that path when arity is unchanged.
`compileMany_length` derives that the ordered template rebuild preserves
arity. Initial `mkEdge` constraint validation keeps its existing adapter;
this module does not silently bypass validation of newly supplied constraints.

`makeNode` removes every edge with an `EmptyNode` child. It sorts and removes
duplicate edge identities before the node-cache request. `canonicalEdges_ids`
proves that the stored node key is exactly the existing source canonical-ID
construction. `makeUnion` follows source union-member flattening, identity
deduplication, empty and singleton cases, and the all-ordinary edge fast path.
The source invariant that stored union-member lists are already flat remains
part of the validity of captured records.

Ordinary and union identification compute the maximum child Mu depth and the
canonical union of child free references. `maximumDepth_exact`,
`childFree_member`, and `identifyNode_metadata` give those exact equations.
Mu metadata reads its completed body, adds one to depth, and removes its own
recursive reference from the free set.

## Separate counters and complete records

The state has independent edge and node caches. It also has first-writer
tables for the complete immutable edge and node records. These tables model
the payload of each canonical entry separately from its key/identity ticket.
An edge record retains its complete child nodes. An ordinary node retains
its canonical edge list and cached metadata. A union retains its member
records. A Mu retains its body and both probe records.

Hits return the previously stored whole record. They do not recompute metadata
from a later candidate. `edgeStep_replay`, `nodeStep_replay`, and `replay`
prove equality of complete records and the entire final state after any
extension of all four tables. Both allocation counters remain unchanged.
`compile_replay` applies that result to the recursively generated template
program. It has no supplied whole-template identity-preservation premise.

`family` traverses the original finite template syntax. `warmup` constructs
each resulting request at a fixed argument. `family_identity_image` proves
that every later member of this derived family returns one of those fixed
canonical identities and changes no cache state. `warmup_length` bounds the
recorded result list by the actual syntax family length.

## Enclosing Mu protocol

`compileBody` compiles the callback and applies the source root self-reference
filter. It reconstructs a union only when the selected bare reference occurs
among its members. Other references and nested occurrences remain.
`probes` runs this normalized body at `RecDepth` and then at `RecUnint` of
the resulting cached depth. `finishMu` uses both resulting node
references as its key. On a miss it reserves and installs the node identity
before it runs the same normalized body at `RecInt` of that identity. It then completes
the stored record. `createMu` applies the source unused-binder and bare
self-cycle cleanup cases afterward.

`compileBody_ordinary` derives that every node request generated by the body uses
an ordinary or union key. It cannot request the Mu entry currently being
identified. `compileBody_preserves_mu` and `finishMu_miss` prove this property for
the actual pending record slot. Thus this fragment does not assume that a
recursive cache hit is safe while its strict body is still incomplete.

`probes_replay`, `finishMu_replay`, `internMu_replay`, and `createMu_replay`
derive the same complete canonical binder or cleanup result after arbitrary
later table growth. The whole result, both probes, cached metadata, and both
counters are retained. `unary_two_cache_example` checks a recursive unary
template by kernel evaluation: three edge allocations, four node allocations,
depth one, and no free references. `self_union_canonical_example` checks
that an added bare self operand leaves the canonical recursive record
unchanged. `self_union_cleanup_example` checks the unused-binder cleanup.

## Remaining source boundary

`Valid` states the two cache reservation invariants. `InternedRecordCoherence`
derives complete key/record coherence and payload coverage from construction
traces, including the normalized binder body. Arbitrary supplied captures
still require their record and metadata invariants. Replay does not certify
forged records.

The finite identity-image theorem is for the syntax-derived constructor
requests at a fixed argument. Connecting every request made by the actual
recursive `substitutionPlan` and epsilon traversal to that family remains a
separate step. In particular, open captured nodes may need their own rebuilt
family when an enclosing environment changes. Captured records here are fixed
inputs, not callbacks that can inspect a newly assigned identity.

Generated nested Mu templates also require a stronger pending-key proof.
Their body can issue Mu requests, so the disjoint-key argument used here is
insufficient. Equal probe identities must determine the required structural
callback behavior under actual outer-reference environments. The earlier
`exotic_probes_incomplete` counterexample shows why mere totality cannot supply
that contract. No unrestricted HOAS callback claim is added.

Consequently this module does not yet discharge the complete
`LexicalBoundedBuilder.RowsCorrespond` interface. Hash-table implementation,
typed cache selection, concurrent lazy-body forcing, and finite machine
identity limits retain their existing separate boundaries.
