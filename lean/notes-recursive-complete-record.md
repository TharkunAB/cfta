# Complete recursive records from shared constructors

`RecursiveCompleteRecord` ties four independently proved views to one
checked body: runtime fields, support, diagnostic inspection, and original
occurrence metadata. Its equalities concern the local checked compiler.
They are not supplied whole-family correctness laws.

Finite inputs supply their own inverse, support, diagnostic descriptor, and
unweighted probability contracts. Retained mass inputs select the weighted
route. Occurrence, map, pay, label, flat choice, and heterogeneous join
constructors derive the matching fields for their results. A join reads
all four views from the same typed operation and argument chain. Names
change only the diagnostic view.

`accepted_guarded` connects the original public occurrence test to the
common value recipe. `support_exact` then equates the actual shared support
binder with the independently compiled term classes. `ranks_exact` gives
every bounded term preimage from the same checked program. `sampling_exact`
connects both source runtime routes to its full ranked distribution.
`inspection_valid` derives the descriptor required by diagnostic closing.

`RecursiveCompleteExample` builds the existing heterogeneous two-key family
through these combined constructors. It retains nine-to-one masses, a
nested nullary join, a delayed mutually recursive member, and distinct
argument names. Its checked program, support records, and inspection
records equal the independently established versions. The delayed member
has the original global inverse rank and belongs to this record's support.
The computed runtime flags retain both mass weighting and terms at each key.

`RecursivePlainApplication` adds ordinary application to these complete
records. Its `Plain` invariant excludes retained key mass in every plain
recursive environment. Application combines the two weight flags directly
and requires both term callbacks. It does not use keyed-join promotion.
The local unweighted probability laws follow from both operands. All four
record views use the same `Apply` compiler. Plain occurrence, map, pay,
label, and choice preserve this invariant. Family assembly has no retained
key-mass flag and uses exactly the disjunction of its body weight flags.

`RecursivePlainApplicationExamples` checks a delayed application inside a
mutual family. The probe has no term callback; the term rebuild supplies it.
After two size units, the delayed member has value one and mass one. The
focused Haskell probe `/tmp/mcfta-plain-application.hs` checks the corresponding
mutual values, uniform and nine-to-one product probabilities, every inverse
rank, and support acceptance. It passed in the project Nix environment.

These results cover the stated typed constructor fragment. Arbitrary
Haskell builders that change shape across probe contexts remain outside the
fixed typed program. Physical sharing, IO, and graph interning retain their
separate implementation contracts.
