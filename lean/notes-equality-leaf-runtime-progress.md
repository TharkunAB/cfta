# Actual runtime edit and requirement progress

`EqualityLeafProjectionRuntimeEdit` and
`EqualityLeafProjectionRuntimeForest` construct witnesses directly in the
actual output cache. The worker executes first. The proof derives its finite
later occurrence witness, then trims that witness back to the actual cache.
The theorem retains the exact returned complete value or ordered value list.

`edit_progress` uses retained physical target values. Each target has a
closed finite raw leaf representation in the input cache. The earlier
physical-target agreement theorem removes target-building effects.
`require_progress` preserves the source old-arity checks and deletion order.
Both operations retain all future leaf endpoint conditions.

Each result has occurrence progress under the finite raw leaf rank. A
changed physical node reference, or ordered forest reference list, forces
a strict decrease. This follows from exact compiler replay of the old and
new witnesses in the same actual output cache. It does not assume that
syntactic representations are injective or carry proof-only cache state
into the next runtime pass.

The forest theorems preserve original child order and support an arbitrary
starting offset. They supply local source steps for the complete equality
schedule. Snapshot path collection, class target folding, and the fixed
multi-pass schedule remain separate compositions.
