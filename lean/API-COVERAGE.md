# Public API and source correspondence

This inventory covers all 66 Haskell source modules under `microcfta/src` and
`microcfta-generator/src`. It includes exposed internal modules and the three
private modules. It uses the source rebased on `origin/microcfta` at `d7f7c11`, which includes
the `tidy/core-formula` work and the subsequent formula syntax extension.
The model names below refer to files in `MicroCFTA/`.

A checked executable model is a Lean implementation with semantic theorems.
A reference model specifies behavior independently of the optimized source.
A contract states an external or representation requirement. Neither a contract
nor a passing Haskell example proves that a source algorithm meets it. This is
a source correspondence inventory, not a claim that the Haskell was extracted
from Lean. Each row states the remaining connection explicitly.

## Observable meanings

| API family | Meaning required of its results |
| --- | --- |
| `fromAutomaton`, finite or depth-bounded | One rank for each distinct accepted term. Overlapping runs must not add ranks. `DistinctRank.bounded_unique_rank` states the exact finite bijection. `Symbolic.union_count` covers the inclusion-exclusion count operation. |
| `elements`, `fromIndexed`, `pool`, choices, products, joins | One rank per retained member. Equal values, and sometimes equal constructor terms, can have different ranks. `Decoder`, `Probability`, and `Shrink` retain that multiplicity. `ranksOf` returns every matching member rank; `rankOf` returns the first. |
| `frequency`, `oneof` | Weights apply to alternatives. Equal branch weights do not make all members equiprobable when branch counts differ. `Probability.eventMass_frequency` gives this law. |
| `uniformly`, `uniformlyGrouped` | Alternatives are selected by their member counts. This policy differs from equal branch weights. `Probability.count_weighted_uniform_rank` gives the arithmetic requirement. The recursive adapters must use the matching size counts. |
| Recursive generation and `upToSize` | Size classes count members. Finite atomic choices can retain their internal weights. Unequal weights on recursive alternatives are errors; non-atomic finite weights can be replaced by member counts inside recursion. `SizeMass` states the class mass and retention laws. |
| `pmf`, `pmfAtSize` | Equal output values aggregate their masses. They do not merge replay ranks. `DistinctRank.rankMass_eq` proves the corresponding rank/term aggregation law. |
| `terms` versus bounded denotation | The suspended enumerator can stop at recursion and return markers. `plainTermsAtMost`, `denotationAtMost`, and depth-bounded imports describe bounded complete terms. `Language.mem_enumerate_iff` and `RecursiveSize.mem_enumerateAtMost_iff` use separate height and node-count bounds. |
| `minimize`, `reduce`, `minimizePoolOn` | Similarity can retain representatives and remove distinct valid terms. This is not the complete-language contract. `Guards.representative_preservation_is_not_language_equality` and `PublicResult.representatives_do_not_preserve_language` separate the meanings. In particular, `minimizePoolOn` intentionally removes less-specific pool entries. |
| `compileWith`, `validOutcomes` | Failure and solver uncertainty remain errors. A successful result must contain every admitted candidate under the supported theory. `validOutcomes` preserves candidate multiplicity; it is not a distinct-term quotient. |

A concrete source check distinguishes the first two rows: `node "x" (oneof
[pure 7, pure 7])` has two member ranks with one constructor term. Importing
its support has one term rank. See `notes-distinct-rank.md`.

## Error and boundary ledger

Errors are not accepted terms and must not be counted as such. A successful
finite empty denotation differs from an unsupported operation or an unknown
solver result. The actual facade sometimes represents an empty generator as
`Left EmptyGenerator`, while reference enumeration returns an empty list.

| Error family | Concrete source cases and required interpretation |
| --- | --- |
| Empty and weighting | `EmptyGenerator`, `EmptyRanked`, nonpositive weights, insufficient weighted tickets. Reject invalid sampler domains; preserve a separate mathematical empty language. |
| Rank/value selection | Negative rank, rank beyond cardinality, `TermNotInLanguage`. No invalid rank may decode. Callback bounds remain caller obligations for indexed sources. |
| Availability | Opaque inspection, unbounded finite query, recursive term inspection without a retained term index, deferred source requiring compilation. These do not assert that the source language is empty. |
| Unsupported recursion | Weighted recursive alternatives, recursive operation family, constrained cyclic imports, ambiguous cyclic imports, unguarded recursion, bounded unresolved recursive occurrence. These are explicit limits of the current compiler, including on mathematically meaningful languages. |
| Structural/codec validation | Invalid support, wrong arity, open references, recursive guard reads, missing root observation, child forest with other than one term, undecodable constructor, datatype derivation errors. Reject before relying on the corresponding representation invariant. |
| Logical/solver uncertainty | `SolverUnknown`, timeout, pruning/similarity/minimization failures, unresolved relational equality or syntactic equality, residual guards. Unknown is not a proof of rejection and must not produce a successful incomplete enumeration. |
| Integer/refinement support | Uncountable/unsupported lattice expressions, integer leaf reads that cannot be compiled, inexact measures, root condition applied to a non-constructor. The supported syntax and domain must be explicit. |

## Assessment

Every source module and exported function family has a semantic role above.
The checked development covers language semantics, distinct-term indexing,
member indexing, probability, arithmetic, and shrinking. It also contains
executable source drivers for suspended enumeration, recursive symbolic
count/select/rank, recipe compilation, pruning, and complete finite minimization.
These drivers expose errors, callbacks, caches, and operational choices.
They are more than abstract contracts. Their local theorems and composed
examples do not establish every whole-driver invariant.

The principal remaining positive proofs are the suspended enumerator's full
acceptance invariant, symbolic context/cache adequacy and full bijection,
heterogeneous recipe/value/support preservation, source binder allocation and
alpha-renaming, and concrete callback-record consistency. Explicit fuel does
not prove unbounded termination. The complete minimization model instead
has a checked counterexample that loses all terms at the selected root.
Complete-language preservation is therefore not a valid general claim.

Generic discovery has a finite executable worklist and whole-root language
theorem. Dynamic type allocation remains its representation bridge. Template
restriction has an exact explicit-state product proof. Finite generator
composition derives member counts, ranks, grouping coverage, and masses.
The API distinction between distinct terms and retained members remains
necessary; equal values need not have unique member ranks.

External contracts are narrower: Haskell primitive/runtime behavior, total
user codecs/index callbacks, lawful random draws, and sound solver answers.
Diagnostic rendering and user effects do not prove semantic correctness.
No source algorithm is marked correct solely because tests pass. No generic
contract substitutes for an unproved internal algorithm invariant.
