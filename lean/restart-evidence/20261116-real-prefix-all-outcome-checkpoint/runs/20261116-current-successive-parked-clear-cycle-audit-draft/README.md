# Successive parked clears and historical proper-path cycles

Status: source audit and rejected two-slot candidate. No new Lean theorem was compiled. No accepted-source counterexample was established. The full one-assignment completion objective stays open.

## Result

Two consecutive genuine selected parked clears cannot erase the two opposite edges of a proper-path cycle. The first parked clear creates `EnumerationDischargeHistory.IsolatedPending`. Its `incoming` field excludes every stored suspended reference to that class. The second actual removed bucket is a stored bucket at the first parked endpoint. It therefore cannot contain the opposite edge.

This conclusion also applies with intervening operations IF their actual prefixes preserve that same certificate. Existing local shared-operation lemmas provide such preservation under exact source-input and protection conditions. This audit does not establish that condition for every arbitrary-budget prefix of the current real-narrow worker. A final-output certificate alone must not be treated as preservation at every intervening prefix.

## Exact existing application

1. `SourcePruningEnumerationRestart.selected` derives `Ready` and `IncomingAvoid` from the actual selected restart and its original `Packet`.
2. `SharedPreparedRecursive.parked_singleton_removed_bucket_receipt` extracts the actual first getValue/checkRepeated/setValue/adapt/restart operations. It retains the entire removed bucket and raw targets. The shared restart has the same native endpoint.
3. Feed that actual read, true recursion check and adapt equation to `EnumerationDischargeHistory.packet_parked_created_isolated`. The result is `IsolatedPending first firstHandle parked.core`.
4. Apply the same raw-bucket receipt to the second actual prefix whose input is this `parked` cache. Its `stored` equation locates the second removed bucket in `parked.core.values` at its real canonical owner.
5. For every member `sc` of that second bucket, the first certificate gives `not (UnionFind.SameClass parked.core.representatives first sc.var)`.

The final proof application uses existing fields directly. It needs no finite model, native-domain inhabitance, independent bucket witness, or new cache predicate:

```lean
-- isolatedFirst is DERIVED at the first actual parked endpoint.
-- secondStored and scMember come from the second actual removed-bucket receipt.
exact isolatedFirst.incoming
  (.unenumerated (some secondHandle) secondBucket)
  (List.mem_of_getElem? secondStored) sc scMember
```

The local variable `first` is the first selected root. The first packet-derived `Ready` fact makes it the canonical owner. The second bucket may use any raw target that aliases this root: `incoming` excludes the entire UF class, not only the raw numeral. This argument excludes a back edge even before its path is required to be proper.

For a sequence of clears, this application requires each older certificate at each later clear input. Under that actual-prefix invariant, a later removed bucket cannot point back to any older cleared class. A closed cycle made only from these historical buckets is then impossible. This is a conditional inference, not a new proved all-history theorem.

## Existing preservation and its scope

- `IsolatedPending.through_frame`: actual representative compression preserves the slot, root and incoming exclusion.
- `IsolatedPending.through_checkRepeated`: the next actual check at a different ready root preserves the certificate, on its true and false branches.
- `packet_restart_ne`: an isolated recursive native boundary cannot itself be selected again. It derives this from the actual packet, native lookup and recursion-boundary fact.
- `PreparedSharedChildIsolation.prepared_stored_child_inputs`: derives child input avoidance from an actual stored parent bucket, actual `CachedOwn.prepare`, its staged child and a certificate at the CAPTURED input. It does not assume arbitrary descendant input avoidance.
- `SharedChildIsolation.prepared_retained_protected_isolated_pending`: uses those derived inputs to preserve the certificate at every actual retained shared-child result tag.
- `SharedEagerReservation.runEager_finite_complete_resources_program_slots_isolated`: retains every ORIGINAL isolated marker in emitted outputs of the actual configured shared worker at its derived sufficient bound. Its header includes the original Packet, Fits/Heap, selector, reservation, mass and ProgramSlots conditions. This is not an all-arbitrary-budget/prefix theorem.
- `PreparedRecursive.parked_tail_created_isolated`: connects an actual parking event to its own remaining admitted ResourceHistory and output. This is the older prepared history API. Its documentation explicitly excludes borrowing a marker from a different sibling or head. It is not an equivalence with the current shared execution.

A valid cross-clear proof must apply these laws to the actual branch and captured states. It must not pass a newly created certificate backward to an earlier captured parent. It must not infer an intermediate certificate from a final certificate.

## Rejected two-slot candidate

Let `H` be a real native heap and `u` an actual stored closed recursive native handle with successful lookup and `recursiveBoundary = true`. Use two identity UF roots, slots 0 and 1, no fragments or residual guards, and a singleton trie whose represented path is `[1]`.

Seed both ancestry lists with their actual `recursionKey u bucket`. All native lookups can use this SAME real heap; no invented native type is needed. Both candidate flags are true. Correct canonical waiting counts are 1 at each root. Therefore `EnumerationPureSelection.find = some []`, selection is `.stuck`, and noStop restart rejects with an empty raw list. The actual selected worker cannot perform the first clear.

If one instead calls the real `checkRepeated` function directly at slot 0, its implementation can clear that bucket after the ancestry lookup. That raw operation does not test incoming references. Repairing the indexes would make slot 1 selectable; a second clear could then leave both buckets empty and selection `.done`. This describes a candidate made from real primitive operations with an INVALID first selected-step premise. It is not an actual source-worker execution. `referenced_clear_not_isolated` explicitly proves that its first clear lacks the certificate created by a genuine selected parking event. The primitive equations for this candidate were not compiled here.

`selected_clear_proper_cycle_unsatisfiable` formalizes the stronger relevant fact for a CURRENT stored closed proper-path cycle: an actual selected clear cannot remove its obstruction. The table above is therefore not a source or Haskell defect.

## Recursion keys and metadata do not replace the invariant

`EnumerationState.recursionKey` deliberately omits target variable identities. It retains the native handle and canonical trie sets. Replacing slot 0 by slot 1 in an otherwise identical suspended constraint leaves the key unchanged. A repeated key does not establish that the old and new raw target equations coincide, or that their witnesses agree. `KeyAncestry` bounds trie-list shapes; it does not restore omitted target IDs.

`Metadata.pending` contains template-pattern/raw-hole groups. It is not a log of erased suspended buckets. The actual parked receipt gives `updated = metadata`; the parked clear does not append its bucket to this field. `SourcePruningResume.Refutes` and `resume_refutes` preserve a refutation for template groups. They do not establish one compatible assignment for erased suspended buckets. `stop = none` bypasses only the metadata stop rule; `.stuck` still rejects.
