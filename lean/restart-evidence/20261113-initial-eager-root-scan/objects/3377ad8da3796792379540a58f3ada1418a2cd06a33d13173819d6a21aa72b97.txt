# Same accepted outcome and initial eager scan

Status: HEADER AND PLAN ONLY. Do not implement a conditional repackage law.
The Root-reviewed worker239 is public and checked. This proposal attaches
it to the actual accepted_initial_prefix producer at the same witnesses.

The proposed accepted_initial_root_scan_origin is a genuine producer
strengthening. Its original source and configuration inputs are unchanged.
Its baseline is the actual current accepted_initial_prefix header.
The new header changes its name, wraps only the old bound/outcome tail in
parentheses, and appends one all-larger-fuel scan observer. Every byte of
that original bound/outcome predicate remains present. The old initial
allocation/Packet/ProgramSlots/capacity fields remain present as well.
The zero-context delta and inverse make this retention reviewable.
No new public predicate, datatype, provider or configuration is added.

The additional guarantee is about the SAME stable returned outcome.
At each bound + extra, an actual positive-depth initial expansion and
ordinary preparation identify that outcome as finish 0 of the actual scan.
Each reached indexed row supplies its own sibling caller/queries, original
source filter interval, exact row children and CachedOwn preparation fields.
The entire intermediate preparation pair remains attached. Prefix stops,
stopped scans and output order retain their literal existing outcomes.
Depth zero and non-active observed branches keep True. No expansion,
ordinary preparation or nonempty output is asserted merely from acceptance.

Implementation plan after Root approves the exact header

1. Call accepted_initial_prefix ONCE with the unchanged original source,
   formulas/solver, metadata/pending premise and configured operations.
2. Unpack its SAME fields/cache/value/heap/build and handle/decode receipt,
   startup/Packet/capacity witnesses, common bound/outcome, full initial
   prefix observer, full resources and complete per-output readback tuple.
3. Repackage all those original witnesses and the whole old tail intact.
   Do not call accepted, a second initializer, a second eager worker or a
   second rootPartial producer. The original readback proofs are retained.
4. Introduce extra. Case depth. Zero has True and makes no scan claim.
5. At depth = succ smaller, invoke initial_runEager_prepared_root_scan_origin
   at the SAME cache/value/heap/build/handle/decode, workFuel = bound + extra,
   predecessor smaller, initialCaller and initialization globals.query.
   Its width is enumBits lib query signed (Nat.succ smaller) + 2. State
   this width explicitly after the depth case to avoid the old cast issue.
6. Retain its concrete child and actual continueWith(resume predecessor)
   hook using the actual prefix's updated metadata. Use its SAME actual
   decision/prefix/preparation observations. Its original source and own
   fields are observed facts; no member/Ready/Packet supplier is added.
7. The preserved old retained.1 extra already says runEager = outcome.
   Rewrite the NEW goal's outcome backwards with that SAME equation, then
   use the checked worker observer in the positive branch. Align known
   constructor receipts where generated matchers need it. No execution is
   repeated by these proof observations.

Scope and comparison

The old accepted producer already proves stable resources, Program readback,
initial slot0 selection and prepared-row membership in original source rows.
The new producer additionally ties its SAME common outcome to the concrete
ordered eager scan and full per-position source/own preparation receipts.
The worker theorem alone starts from supplied current startup witnesses.
Here acceptance itself produces those witnesses and the same common bound.

All old accepted modes remain: arbitrary checkEmpty, metadata/order and
signed source budget. Its global worker is still noStop (stop = none).
The generic worker239 separately covers arbitrary stop. This proposal does
not invent a common global bound for stop = some, change the default flag,
or force depth > 0. Joint finite Type completion, source typing, model
existence, output existence and Haskell correspondence remain open.
There are no Haskell edits or fixes in this proposal.
