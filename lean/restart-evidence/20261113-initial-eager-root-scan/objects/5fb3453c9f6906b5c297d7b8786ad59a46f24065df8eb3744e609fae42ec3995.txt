# Literal default hooks: local laws and exact remaining scope

Status: HEADER/PLAN only. No body, compiler, probe or live source change.
Authority: the committed 96-line default-entry plan in the initial-shared-visitor
packet, copied here without modification and pinned in source-pins.json.

1. Exact existing callback law.
   SourcePruningRecordTypes.recordTypes_empty:76 already states pure false plus
   the exact types update for EVERY input, fuel, Core and pending list.
   It supplies a singleton raw success, unchanged Core and no oracle reads.
   pending, typing and openHoles remain exact record projections (:24-32/:50-56).
   The callback header only packages these existing consequences.
   Initial pending=[] remains empty by this equality at each reached callback.
   recordTypes_inr:83 is stronger for Right events: all metadata stays exact.
   Whole execution preservation still needs the actual callback induction.

2. Narrowing is not controlled by the empty template or pending list.
   OuterNarrow.narrow:11-21 reads value shape and metadata.types, then uses
   NativeView.narrowAt:33-44. Mu and incoming type members already have exact
   identity laws narrow_mu:24 and narrow_type:36. Otherwise true fits/admits
   makes keeps:21-30 true, but head exposure and makeNode still execute.
   Neither templates nor pending appears in this decision. Empty catalogs alone
   do not establish identity, and filter identity does not establish heap identity.

3. Smallest justified physical identity cut.
   native-header takes the actual makeNode computation and its CURRENT input
   Facts/edge residency. It supplies no desired Normal, identity, Ready or model.
   Derive its exact output Facts with InternedNestedFacts.node_verified:100.
   Derive its empty/node shape with RequiredCache.node_ordinary:73.
   Derive exact allocation-free reconstruction with
   EqualityOrdinaryReadback.makeNode_normal:34, using the same constructed state
   and reflexive growth. This is the needed physical cache-hit fact.
   Ordinary head exposure returns its stored rows and same heap at every fuel;
   NativeView.narrowAt_complete's secondRead proof:126-136 uses that exact fact.
   All keeps tests are true, so List.filter_eq_self removes the filter.
   Rewrite the derived reconstruction to obtain result=value and after=before.
   Existing normal_grows:19 transports the reconstruction through actual growth.
   The same makeNode receipt may be observed earlier in a native history; it
   must be the causal source of this value, not an independently chosen value.

4. This ordinary construction case is not the full current Value domain.
   Union/reference fallback still performs head exposure and ordinary rebuilding.
   NativeView.narrowAt_complete:60 returns an Ordinary result. It does not say
   that an input Union or reference retains its complete physical identity.
   Ready/Available/closed by themselves do not establish ordinary reconstruction.
   No reachable counterexample or Haskell defect is claimed by this audit.
   The whole worker must derive an adequate per-slot case split from actual
   source history, or relate differing handles/heaps by an actual simulation,
   or install a literal identity hook in one shared backend with exact old wrappers.
   An arbitrary future neutrality/simulation proof is not an acceptable input.

5. Actual order specialization.
   The literal Haskell default is noExpansionPreference, not typesLast.
   Use order=(fun _ _ => none) and stop=none, as Enumeration.hs:913-927 states.
   Then Restart.decision:15-23 ignores metadata in every remaining candidate test.
   An arbitrary metadata-dependent order cannot be erased. In particular,
   RecordTypes.typesLast:35-39 reads types even when pending is empty.
   A types update can therefore change its candidate choice. No such generic
   order equivalence is proposed. A metadata-dependent stop has the same issue.

6. Reuse the existing generic literal-hook APIs before adding a worker.
   EnumerationUntil.enumerateUntil:90 already takes stop, narrow, expandAt,
   order and oracle. Its identity narrow is (fun _ _ node => node), and its
   eager expansion is (fun remaining => EnumerationState.enumerateNode graph remaining).
   EnumerationUntilBridge.no_stop_eager_successes:220 retains ordered successful
   rows and full final Core for that exact specialization and a read-only oracle.
   recordTypes_empty derives its ReadOnlyOracle premise; no new provider is needed.
   graph-header's only new control induction compares existing enumerateFully:301
   with that callback against existing noPruning:332 at constant-none order.
   Empty callbacks are pure false, so induction on enumerationFuel retains the
   entire raw ExceptT list, errors, order, multiplicity and final Core for all fuels.
   Metadata updates disappear from control and the Unit result, not from a claimed
   equality of intermediate metadata. Compose this law with the existing Until
   bridge to retain the literal identity/eager route's successful rows.

7. Shared native correspondence remains the primary operation boundary.
   SharedPreparedRecursiveChildPolicy:39/77/88 exposes child policy, but its
   SelectedStep.runPrefix:43 still hardwires Action.prepare:17 and OuterNarrow.
   SharedPreparedRecursive.continueWith:74 hardwires recordTypes and restart.
   No existing parameter installs a literal native identity narrower in runEager.
   The graph API has static handles and a modeled slot scan. It has no actual
   shared caller, full Memos or physical native heap receipt to cast into runEager.
   Its local erasure law must not replace the required shared-native comparison.
   If a hook parameter is needed, factor the one narrowing operation at Action/
   runPrefix and preserve every old wrapper equation; do not create a second worker.
   At stopped/exhausted prefixes, compare observations that erase extra metadata
   explicitly: existing Failure.exhausted contains metadata. Full Result equality
   cannot silently discard those fields, even when emitted metadata is None.
   Keep all old resource/readback receipts beside the derived observation relation.
