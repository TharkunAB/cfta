Exact branch distinctions

- A nonempty remaining candidate set accepted by every stop-rule test gives decision none. It emits some metadata. The stop test includes blocked candidates.
- No candidate gives some .done. It emits metadata none.
- Candidates exist but every candidate has a waiting key: some .stuck. Restart.run returns raw []. Recursive.resume interprets stuck as normal complete [] so the next sibling may continue.
- Some .expand uv is the only decision that consumes recursive expansion depth. At depth zero it returns exhausted with the actual current endpoint. None/done/stuck are handled before that depth check.
- A singleton true callback prunes normally. A singleton false callback uses its updated metadata and actual callback core. Other callback raw lists, including raw [], explicit errors or unsupported multiple rows, are retained by Recursive.continueWith as a callback stop with the actual Caller/Queries. Callback raw [] must not be silently classified as a successful prune.
- SourcePruningAfterCallbackExact.run_exact:15–45 starts from an actual successful callback and distinguishes prune from stuck in its equation. It does not assert arbitrary callback raw [] or erase fuel errors.

Parked and narrowed paths

A repeated recursion check performs a real pending-slot write with an empty bucket. ParkedRestart.adapt:94–100 reconstructs the candidate flag and removes all old scs waiting occurrences with NativeIndex.write, then retains the actual checked core. Framing that core with the old indexes would be false. Its candidate none is distinct from a recovered cache whose Restart.run gives []. adapt_after_write:114–137 derives the adapter from the producer's actual clear-write/index receipt. Sufficient old count bounds can come from FlatNativeIndex.write_stable/count_stable. Candidate decoding failure remains optional even when count fuel is sufficient.

SelectedStep.runPrefix:42–94 separates readFuel, checkFuel, nativeFuel, representativeFuel, indexFuel and callbackFuel. A false check continues through actual native narrowing, encoding, index adaptation, then concrete Right recordTypes. Missing lookup, failed native preparation, no action, non-singleton action, failed encode, missing cache and callback errors remain distinct observations. Right recording is currently a pure false result and unchanged pending metadata; this does not justify replacing the Left callback, which renders fragments and resumes all pending checks.

Sufficient old-bound gates

Pure restart equality has no bound gate. Flat direct representative reads cannot equal arbitrary insufficient old representative execution: old lookup may return representativeFuel while flat lookup succeeds. For callback transport, a small conditional lemma from an actual old successful callback can induct its actual rendering/resume receipts and use representative_related at each completed old read. CallbackExact then supplies the full old singleton. The producer wrapper derives those receipts from current Safe, Stratified, allocated fragment and bounds on every metadata.pending entry; it does not assume a future callback success. The original Packet contains those current facts.

Keep structural callback/rendering fuel observable. EnumerationState.expandPartial:341–354 emits fuelExhausted at zero, decrements through fragment structure and follows enumerated holes. The same old fuel also pays representative lookup. Removing lookup fuel in the flat worker does not license removing structural fuel or claiming all-bound error equality. recordTypes_moreFuel retains successful results and exact final old cores; it does not say that low-fuel errors persist. Record explicit sufficient old bounds or a genuine completed old read family. Graph.node classifies a pending no-bucket recursive node as truncated; correspondence to the actual native heap remains a separate provenance obligation.

Later recursive transport boundary

NativeContinuations.run:41–71 invokes the concrete callback/recursive hook before the suffix. It threads the hook's reached native Caller/Queries into the next sibling while restoring the same captured enumeration cache. Haskell Enumeration.hs:975–991 confirms branch-local metadata: each sibling starts from the same captured ost', and only that branch's recursive call receives ost''. Do not invent a metadata fold across siblings. Preserve each emitted output's own metadata, cache, Caller and Queries. Keep stopped receipts and absent endpoints. Identity-hook equality proves none of the concrete callback or recursive continuation work.

Remaining work is concrete flat callback execution, parked/narrowed prefix transport and then actual hook-aware recursive composition. This review does not prove whole-enumerator completion, language preservation, a physical IntMap implementation, a host-width result or a stronger H6. No builds, Lean evaluations, native tests, Git, network or repository writes were performed.
