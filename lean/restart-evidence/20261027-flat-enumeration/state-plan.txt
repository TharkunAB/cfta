EXACT TERMINAL PREFIX ORDER

Enumeration.hs:729-749 does this:
1. Record ALL original here representatives in order, retaining duplicates.
2. Union the first ORIGINAL raw variable with each remaining one.
3. Read the actual final representative of the first raw variable.
4. Move waiting counts for DISTINCT recorded roots, excluding that winner.
5. Assimilate each originally recorded RAW slot into the winner, in order.
6. Merge the incoming node and descendant constraints into the winner.

Keep the exact recorded list and exact winner. Rereading the old variables after
union would return only the winner and lose the losing raw slots. Duplicates are
valid: already eliminated sources are no-ops. Waiting movement uses the deduplicated
key set, whereas assimilation consumes the original list.

assimilateUvarVal (489-508) checks target=source, reads raw source, skips eliminated
source, computes source/target intersection, rejects Empty BEFORE both value
writes, writes merged target and eliminated source, then unions source ancestry
into target. Keep sourceScs++targetScs and this argument order. The Haskell target
lookup is let-bound lazily; its textual placement before the source case does
not force it on the eliminated-source no-op.

mergeNodeIntoUVarVal (512-525) instead resolves the actual target, reads its slot,
computes incoming/old intersection, WRITES replacement with gained incoming
constraints, inherits ancestry, THEN rejects Empty. This differs from assimilation's
pre-write rejection. Both can return [], but their logical write receipts and
native caller effects differ.

A graph-based flat-vs-old core refinement may reuse old intersectValues and
hasEmptyContents with the SAME graph argument. This is not actual native
intersection execution. Current SourcePruning producers separately retain reached
native caller/query/handle and Empty receipts. Do not rerun intersection, fabricate
a Graph, or infer rollback of native effects from rejection of a core branch.

EFFECTS OUTSIDE THE SIX FIELDS

Actual Haskell EnumerationState (227-265) has four more fields:
expandableUVars, waitingUVars, edgesOf and constrainedRecursion. The first two
are maintained indexes; the latter two are fixed configuration inputs in the
old model. The proposed type is a CORE, not the entire literal Haskell state.

addUVarValue updates counter, slot, expandable membership and ancestry. A raw
write updates slot and expandable membership. Its waiting count removes lost
occurrences BEFORE adding gained ones, at each occurrence's actual current UF
root. Multiplicity matters. setUVarValue derives gained/lost from the old slot.
Assimilation uses EMPTY gained/lost lists because the references move within
the same class, while still changing both expandable entries.

Terminal union changes UF before its explicit waiting-key transfer and before
loser elimination. Index correctness and LiveRoots can be temporarily false in
that interval. Keep only the operational relation at that intermediate point.
Do not claim every primitive preserves all admission/cache invariants.

EnumerationExpandableIndex.Cached already separates the six-field old core and
indexes. NativeIndex.count/write are not generic over a flat core. A later flat
Cached adapter should keep waiting/expandable fields literally equal at matched
prefixes, use the same actual native heap, use exact root equality for count keys,
and same values+heap for candidate flags. Merely replacing Cached.core does not
prove those invariants. The initial checkpoint need not introduce that adapter.

Haskell branches (368-373) copies the same input state into each alternative,
including indexes/configuration. This does not prove rollback of the separate
native/interner/query effects modeled by other SourcePruning components.

STORAGE SAFETY DOES NOT FOLLOW FROM THE RELATION

Valid + exact-root/size UF Represents + five field equalities do NOT imply
ForestBound or Safe on the new representation. Let flat explicitly store
Root 1 [uv] for EVERY Nat and let the old forest be empty. Flat.Valid and UF
Represents hold, yet at finite counter the flat map has stored addresses outside
the allocation domain. The old map has none. This is a representation-bound gap,
not a defect in the proposed operational relation.

For later admission, derive and retain separately:
  EnumerationCorrectness.ForestBound flat.counter
    (FlatUnionFind.erase flat.representatives).
No new runtime field or proof-carrying State is needed. Initialization derives
this bound. Valid allocated UF calls preserve it; a total UF union on arbitrary
Nat can add unallocated entries, so source operands need genuine bounds there.
Allocation leaves UF unchanged and increases the bound. Valid plus this bound
also bounds each class member. Slots/obligation bounds and LiveRoots retain
their own existing current-state receipts. Do not assume desired final Safe.
