# Prefix reservation interface after Scan-only checks

Reviewed at 2026-10-16 18:01 CEST. This note contains no new reservation theorem. The two new checked modules and their public probes are frozen separately. The per-query Word modules were read as current checkpoint work; their authors own their validation.

`FiniteOrdinaryScanRanges.scan_ranges` now derives the existing Scan range plan from coherent, available finite ordinary records. `local_ranges` derives the Scan-only actual local interface. `OuterVerification` derives Checks for all eight supplied strict read families. These facts do not derive the full local construction plan. Class target and leaf queries remain its live numeric obligations.

The smallest next interface is a reached **query-entry** plan that constrains current counters before the query runs. It must retain the complete Checked state, captured class forest, current slot map, merge memo, and actual query operands. It should check `heap.nodes.next <= 2^bits` and `heap.edges.next <= 2^(bits+2)` at width `bits+2`. These inequalities imply recursive key certificates for current resident finite ordinary operands. Empty-domain requests need no new domain reservation. Do not use `width-2` without the independent condition `2 <= width`.

The plan needs these source entries, in this order:

1. Target operand: actual forest projection, then actual allocated merge. Each returns its exact heap and equality operations. Neither is a checked intersection entry by itself.
2. Fold cons: actual head operand, actual recursive tail, then the intersection of head and returned tail at the tail's literal checked state. `TargetGraph.FoldRanges` lines 129-139 already records this order. Target's seed is its first path; the fold reaches the remaining paths and then the seed operand at the base.
3. Force: a present slot returns the exact prior target and whole shared state, with no target producer or reservations. An absent slot enters the actual Target with `operandPaths record.paths path`; `SharedTargetForce.Force` lines 39-47 records the branch.
4. Leaf: actual Force, then `requestNode emptyDomain target input` at the actual returned shared state. `SharedTargetLeaf.Ranges` lines 41-47 checks precisely this entry.
5. Class pass: finish the tail classes before the current head. A head captures the actual returned forest and starts fresh target slots only. Native, equality, merge, fourth, and global state remain warm. `ClassPass.Ranges` lines 47-54 records the actual tail prefix.

A plan predicate can quantify an entry reached by these transitions and require only its numeric counters. A transition after an earlier operand, tail, force, or class may carry that completed earlier graph. It must not carry the current query's completion, desired language, final Ready, or future result certificate. This is the same distinction used by OuterEntries.Step. It gives an honest conditional resource adapter before an initial allocation count exists.

There is one proof composition issue to keep explicit. `FiniteOrdinaryTarget.operand` lines 111-126 reconstructs an actual operand receipt without any range input. In contrast, its public `fold` and `target` at lines 128-169 still take FoldRanges/TargetRanges. Therefore their full receipts must not be used unchanged to infer the state before the very query whose range is being derived. The private `fold_reads` at lines 86-109 verifies supplied annotated prefix receipts without ranges, but those receipts already contain ready queries. A new prefix adapter must follow actual earlier operands and checked Steps, or reconstruct each earlier query from its own entry capacity and align it using Step.unique. At each stage it must derive the next Ready/domain/residency/certificates before entering the next query. No current-query future receipt is needed for that induction.

The new per-query proof route is suitable for the arithmetic part. WordExecution.Origins.of_valid obtains fixed-source operand readiness for every cell phase from actual physical native validity. Its reached/word_ranges proof tracks the actual checked schedule. At a new target or leaf query, the source may be the literal current machine; it need not remain the initial outer construction heap. Original operand identities, including warm captured owners, must be identified in that current fixed source. Generated earlier results are legal current inputs, but need the numeric bounds at this new entry. Their height bounds alone do not imply identity bounds.

A quantitative layer must count reservations before the corresponding entry. Use separate counts for node attempts, edge attempts, equality-interner attempts, and any nonempty domain reservations in a wider scope. Cache.reserve lines 141-146 increments `next` on reservation, not on successful final publication. Resident-table cardinality does not measure lost candidates or intervening process activity. The existing Effects records give growth and retained tables; they do not give upper bounds on `next`. A finite scalar height bound does not bound row multiplicity, child-slot count, equality payload size, or the number of class paths.

A minimal component count contract can therefore take an actual finite prefix and prove upper bounds of the form `after.nodes.next <= before.nodes.next + nodeDraws` and the edge/equality analogues, with draws derived from primitive source actions. Constructor-only rebuilds, projection heads, merge selection and work, and accepted native result construction must each contribute their actual reservation attempts. Hits contribute zero for their skipped body. Equality Top/accessor construction must retain its actual same-cache behavior. Slot reset changes no interner supply. Derive these counts over independent finite prefixes before using them to discharge whole-root capacity; do not first assume conditional root completion.

This note recommends the query-entry numeric adapter first, then primitive reservation accounting. It does not claim an initial finite-word bound, unrestricted process history, general Mu/reference/union completion, repeated-pass stabilization, host demand order, concurrent cache publication, or concrete GHC/runtime correspondence. No Haskell defect or fix was discovered. Any later Haskell repair must be recorded in the first FINDINGS registry with failure, reproducer, paths, commit, checks, and upstream status.
