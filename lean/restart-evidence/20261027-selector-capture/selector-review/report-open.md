# Selector-to-accepting-edge design and source review

The local semantic fact is direct. An accepted actual ordinary parent contains an actual accepting edge in its stored outgoing list. Ready's linked invariant plus parent availability derive that edge's complete canonical residency at the SAME heap. A permutation of those stored rows retains that same accepting edge. This needs no Graph, child completion, final assignment, or future native execution.

The draft has three theorems and no new predicate or runtime definition. `selected_accepting_of_perm` derives selected membership, original stored membership, actual residency, and edgeMeaning for the same accepted term. `interned_accepting` instantiates it with the actual formal raw interned selector. `canonical_accepting` uses the existing `SourceCurrentEnumerationOrder.canonical_perm` and an explicit correspondence between its CURRENT root-map/fallback rows and the actual stored rows. It preserves optional weighting and duplicates. It adds no comparator-law premise because only multiset retention, not lawful priority/stability, is used.

The distinction between raw and default source order is necessary. Haskell `runsInterned` uses `const nodeEdges`. Haskell `runs` uses `canonicalEdgesOf Nothing`; `runsBy` adds weights; ordered startup also uses the canonical closure. `canonicalOrder` sorts the rows returned by `reachable`, which records each node's nodeEdges. For a node built later, `canonicalEdgesOf` uses the per-node canonical fallback. The installed formal order module models the completed lookup/fallback closure and proves its permutation law. It explicitly leaves actual canonical-class computation, source map storage, sortOn correspondence, and lazy demand as separate bridges. The draft therefore keeps actual row-map/fallback permutation explicit. It does not mislabel raw nodeEdges as the literal default or claim a completed physical default-selector proof.

A custom selector needs a semantic retention condition, in addition to the existing selected-subset admission. The minimal pointwise condition is: for every term accepted by the current ordinary parent, some edge in the actual selected list accepts that SAME term under the SAME native guard interpretation and ambient environment. A uniform policy quantifies over the required ambient environments and terms. Subset membership then supplies original stored membership and residency. Equal list length or a length upper bound does not establish this language condition. In particular, an empty selected list meets subset/length upper-bound checks and retains no accepting edge. `runsNarrowedBy` intentionally permits dropping runs; the missing full-coverage policy is not a Haskell defect.

## Remaining ordered-scan boundary

An accepting selected-list member is not yet an actual reached captured receipt. `NativeBranches.run` stops at a preceding missing or noncontinuable receipt. It advances only completed edges, arity rejection, and the explicitly recognized valid raw-empty child rejection. Thus an earlier unsupported prefix can prevent the scan from reaching a later accepting edge. The hook-aware worker additionally runs the head hook before the suffix. A stopped hook prevents later sibling execution even when the edge itself completed. Its exact output, reason, and optional actual endpoint remain in the stop.

The captured enumeration cache stays fixed for siblings. Actual Caller and queries advance through each continuable edge or hook. A later scan-coverage proof must obtain supported prefix operations and appropriate continuation policy from actual admitted executions, and transport the native model along the actual caller effects. The selector witness alone proves neither prefix support nor callback/recursive completion. No desired final satisfaction or after-invariant is added here. Opaque recursive frontier, pruning-language policy, depth/stop policy, final rendering coverage, and physical Haskell correspondence stay open. All earlier counterexamples and repairs remain unchanged.
