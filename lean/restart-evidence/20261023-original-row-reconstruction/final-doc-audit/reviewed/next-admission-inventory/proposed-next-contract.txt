# Proposed next compositional boundary, in plain text
This is a design proposal only. No Lean header, proof body or execution producer is authorized or supplied.
Keep one actual populated Wrapper unchanged, including its native tables, operations, domains and separate pair memo.
Use two concrete finite input interpretations connected by the existing cross-view Agreement, with the same holds function.
Assume the wrapper already has Stable under the old interpretation.
Require genuine old EdgeInputs for the canonical empty-domain request captured in every returned wrapper memo cell.
Derive Stable for the new finite model and rank family at that exact same Wrapper.
Keep every table link, captured full request, answer, phase, counter and canonical publication witness unchanged.
Use existing empty seen coverage and ContextRebase.edge_law. Retain both sound and bounded-completeness fields; do not erase ranks.
This boundary proves no new cache admission and takes no desired new result law. Its old-admission condition is explicit.
Then derive that condition causally at each real fresh pair publication and preserve earlier cells from a genuine initial certificate.
Combine the native Covered lifecycle and actual reached-control checks with the separate wrapper publication history; do not conflate their caches.
For a closed resident rebuilt root, use the existing grown-inventory producer and InventoryRebase.rebase when its concrete incoming At is available.
The second closed operand can be the same root; the existing rebase API has no distinctness premise.
An arbitrary old InputMeaning/RankedInput requires a separate exact-agreement argument. Choosing a fresh concrete model is not an automatic consequence of H23.
Preserve the old global allocation Trace literally. Deriving a new-source Trace, new-source Room and fresh native word-key admission is a later resource obligation.
