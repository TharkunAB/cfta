## Existing counterexample to phase identity

The selected checked `SelectedProgressCheck.accepted_union_skeleton_growth`
already contains a source-built successful `runClass` on `[first,second]`.
Both input ordinary heights are 1; the returned forest heights are `[3,3]`.
Its source is `selected-progress-kernels-3.source.lean`, selected by the
old component's `selected-progress-selection.json`. Public full group 2
prints that expanded statement. A singleton completed tail is exactly
such a class call followed by the empty fold. It can therefore change the
forest captured by a following head class.

This establishes failure of literal input/output forest identity and of
nonincreasing ordinary-skeleton height. It is not a checked counterexample
to nonincreasing full `InternedValueMass.value`. No such claim is made.
The earlier Merge fixture separately proves that an actual non-Top parent
row can retain its full guard while its recursively merged children change.
Neither example needs to be rebuilt for this investigation.

## Exact contracts already available

`ClassPassPhaseLineage.fold_phase` extracts the actual completed suffix
`records.drop(classIndex+1)`, the current class, and the later prefix.
Its phase receipt derives readiness, availability, domains, stored memo,
global validity, histories and growth at the actual phase entry.
`ClassSelectedChildLineage.fold_selected` correctly passes `phaseValues`
to `class_selected`; `Selection.native` and its SlotReceipt keep that
same phase forest. None of these contracts equates it with preparation.

`ClassFoldRowOrigins.fold` already provides a substantive chronological
root-row trace. A physical root row at a fixed forest slot starts either
at an indexed input root row or at an actual `FoldEvent`, and its
`FoldFlow` retains all subsequent class reconstruction. Its `fields`
projection keeps the full guard and symbol. The event alternatives retain
actual native leaf queries or actual recursive Head exposure. This result
must be reused rather than reproved as another root-row fold wrapper.

Inside its ordinary arm, `Rebuild` keeps an actual `EditChildren` graph,
ordered reads and per-child `Slice` receipts. `SharedEditChildLineage.indexed`
derives each slice. `row_child` derives the selected child's actual
`EditNode`, histories and growth, provided its edit-map lookup is present.
The absent case is literal child identity. These facts describe actual
calls. They do not assert that the returned child equals its input or
already has a `RequiredRowOrigins.Origin` certificate.

`MergePositiveRowOrigins.call` recovers the actual cold or warm physical
writer from Raw history. Its `positive` theorem keeps an indexed source
row, full guard and symbol, and either row identity or actual ordered
recursive Merge requests on its children. It does not turn those requests
into Required origins or a generated-result mass bound.

## Smallest substantive next producer

Extend the actual edit occurrence law to structural occurrences, not just
root `nodeEdges` membership. An appropriate endpoint takes initial class
support, an actual `NodeReads` graph, and
`RequiredRowOrigins.RowAt result positions rowIndex row`. It derives one
of these two outcomes:

1. An exact structural input occurrence with the same full row fields,
   together with the actual ordered edit slices along the visited path.
2. A concrete native leaf or recursive Head event, its actual chronological
   state/call receipt, and the still-unconsumed occurrence suffix inside
   that event's returned value.

The native/Head event is not an arbitrary supplied origin relation. It
must be recovered from the actual edit graph. The suffix is necessary:
the selected row can lie below the event result rather than at its root.
Existing `NodeEvent` describes only a selected root row, so it cannot
represent this case without a genuine structural extension.

In the ordinary case, combine the actual reconstructed row with
`Rebuild` and its child slices. Keep the canonical output row position
separate from the original row position. Canonical filtering and sorting
can change row positions. Child positions remain the same; an unselected
child is unchanged, while a selected child supplies the exact next
`EditNode`. The proof then follows that actual graph. A fold-level version
can consume the already extracted tail and follow strictly earlier class
occurrences. No forest identity or generated-value size premise is needed.

This structural endpoint is useful but does not yet prove the complete
observational projection theorem. `ProjectionIndexedOrigins.rows_indexed`
recovers the exact ordinary projection choice and its remaining `Project`.
Its `union_row` can recover an actual `Read` which unfolds Mu. Such a read
does not imply a stored structural `RowAt` at an earlier heap. The full
joint theorem must keep that actual Head/unfolding interval and fixed
reader, then compose the event-specific native and Mu origin producers.

## Assumptions that cannot be silently added

`RequiredRowOrigins.Origin` has identity, hereditary plain-region and
ordinary-row cases. It has no class-native conjunction/event constructor.
There is no general producer of `All₂ Origin prepared phaseValues` in
the class phase contracts. Assuming it would replace the missing proof.

`ActualClassRowOrigins.fold` is a specialized alternative: it preserves
one continuation under every record's `Unselected` condition and the
explicit initial `Root` condition. A path selected by an earlier class
does not meet those hypotheses in general.

`EditDomains.Safe` and `ProjectionPathDomain.ForestClosed` require
closedness along selected paths. They do not assert
`SourceMemoGate.unconstrained recursiveValue = true`. Class edit workers
can run actual recursive Head exposure. Discarding every positive Head
event requires the separate accepted gate certificate and causal guard
heap used by `ActualPlainHeadOrigins`; phase readiness alone does not
supply the gate. The existing Head-chain receipt retains real unfolding
calls but explicitly does not identify reconstructed rows with earlier
nested source bodies.

The recommendation is to implement the actual structural event/suffix
producer next, then consume it in the projection proof. Do not add a
generic supplied-Origin transitivity/rank wrapper. Renewal bounds, general
completion and initial-operand ancestry remain separate obligations.
