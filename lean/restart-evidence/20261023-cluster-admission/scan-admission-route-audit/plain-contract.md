# Proposed compositional boundaries

First boundary: for the actual Scan interpreter and an identical initial control and full Wrapper, any two completed executions return the same ordered kept list and full Wrapper. Both finite execution equations must be proved. No physical or semantic invariant is needed for this operational equality. The proof must preserve all terminal outcomes when the fuel increases.

Second boundary: for one original-parent symbol bucket and one fixed concrete input inventory, add native Covered and captured-pair admission to a genuine completed scan. Keep parent admission, all existing current invariants, the initial populated tables, width, initialDomains, global allocation Trace and original Room reservation explicit. Each comparison obtains its exact H28 done witness once; H25 uses that same witness. Native and pair admission are separate results.

For route B, a separately proved admission-preserving completion from the same control and starting Wrapper can be identified with H20's completion by the first boundary. The ordered result and full Wrapper must both be rewritten. Keep H20's membership, length, all-ambient physical language equivalence and complete returned packet. A proved completed-past preservation theorem for any supplied scan done equation would also avoid a second completion construction; it still needs a real phase/readback induction.

Third boundary: augment each already supplied H22 Fin-chain execution at its same boundary. Keep the selected entries, reversed buckets and exact list order fixed. Retain admission at every state, not only the last. Then carry it through H23's literal raw reconstruction by unchanged-cell advancement.

Before a generated root is a later operand, use the actual closed resident root to construct the expanded inventory and prove agreement on the old admitted domain. Rebase native contextual laws/Covered and pair Stable on the same populated caches. Existing Inventory.At and H24 provide these transport interfaces. New-source scope, domain-history reindexing and Room are separate obligations.

This is a plain proposal. It supplies no exact Lean header or implementation authority. Literal modeled Mu rows, generated-parent admission, public traversal and Haskell refinement remain outside the result.
