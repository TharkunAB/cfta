## Next source-anchor handoff

An epsilon Origin is not a proper original-source occurrence. `MergedFreshOrdinaryGraph.successors` unfolds Mu values by the actual repaired stored executor at the supplied view and discards that call's returned heap. A resulting Origin cannot by itself provide an original source row index, an inherited-path decrease, or ancestor-key exclusion.

There is a stronger available normalization fact. `PublicationFilterSource.filtered_row` proves that actual self filtering followed by bare-self erasure preserves `LiteralRootParts.Row`. This relation traverses root unions and exact ordinary rows only. It does not unfold a Mu atom. With the actual winner/ordinary/filter equalities, the selected physical output row can therefore be traced to a literal raw root row rather than only an epsilon Origin.

`LiteralUnionParts.row` then passes that literal row through the actual union constructor to an exact member call. `StoredSubstitutionOrigins.node` already retains an original row index, full symbol and guard, ordered child Calls, and their literal prefix and suffix heaps. The next general composition should retain these exact witnesses through source union members and strict stored-Mu bodies.

The existing `RecursiveHeadRowOrigins.BodyRows` leaves its stored-Mu case as `True`. The existing `RecursiveHeadChainRows.Rows` supplies actual chronological union choices, stored-body calls, terminal ordinary rows, and warm child calls. It does not identify a generated terminal row with an earlier original stored-body occurrence. The new stored-Mu physical-row producer advances that specific missing case rather than replacing the existing chronological producer.

For recursive root-union composition, a later interface should accept a literal root `Row`, not only `nodeEdges` membership. A member call can return a mixed union containing the selected ordinary row. The same cleanup argument excludes Mu and Empty for a literal row, but this generalization is separate from the current selected-physical-row contract.

Arbitrary replacement values require a separate origin branch. `execute_reference` can return a composite replacement with rows absent from the original reference source. A universal original-source occurrence theorem cannot omit replacement provenance. Source-derived replacement anchors must therefore accompany the recursive relation. Strict stored-body descent alone does not prove the global outer measure.

A concrete next producer is an induction on the original stored Value size for literal rows of an actual substitution result. The ordinary case uses indexed NodeRows. The union case uses actual indexed member Calls and literal union normalization. The open Mu case uses the strict original body call under the sparse shadow map. The closed case retains the literal source subtree. The reference case stops at an explicit replacement-origin alternative. Native ordinary callbacks replace names with bare references, which have no literal Row; that specialization can remove the replacement-row alternative. This would identify an original stored-body ordinary row, not yet an initial public-source occurrence or a decreasing outer request.

Retained used-Mu epsilon exposure, general original ordinary-row lineage, consecutive outer source-anchor handoff, all-active-owner key exclusion, and general outer completion remain open. This checkpoint does not establish a Haskell runtime defect.
