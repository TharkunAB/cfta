# Next constrained caller producer

Reviewed on 2026-10-17. This is a bounded source survey, not a new theorem or an execution test. The accompanying headers file copies the selected declarations from 20 pinned production files.

## Next producer

Implement a numeric resource producer for one **actual selected Operand**, then compose those producers in Target order. Suggested boundary: `MixedOperandResources.complete`. Its inputs should retain the initial `MixedTarget.operand_complete` physical, selected-domain, Merge, and global-memo facts, plus `GeneratedQueryResources.Frame` and `Fits profile before`. Its result should construct its own existing Operand graph and full receipt, retain the causal native and Merge laws at the same returned checked state, and derive `Fits (operandForecast profile values.length path.length) after`. The forecast must be a pure function of initial numeric bounds and literal input lengths. It must not contain an actual return, a supplied future counter bound, or a range plan.

Keep the numeric producer independent of a hereditary-only operand restriction. A conditional cap result can reuse the existing mixed proof. Available Mu, union, and reference payloads must follow their actual source branches. An initial literal forest length is necessary for the generic Operand API: availability does not bound the number of repeated entries in an arbitrary list.

The main missing internal producer is a general Merge `Run`/`Call` mass-and-counter bound. The proof must include actual `.select` work and keep-first winners. Projection needs its own corresponding bound. These two computations occur before the next checked native query. The current query forecast does not cover them.

## What is already closed

* `GeneratedQuerySequence.complete_many` constructs a finite indexed program over initial values and actual previous results. `Supported` checks indices against the growing pool. `Reserved` checks only the pure entry forecasts. It does not describe an interposed projection or Merge.
* `MixedTarget.operand_complete` already constructs the selected projection followed by Merge, with its full receipt and retained cap/native/Merge stores. It does not return a causal numeric mass bound or a supply forecast.
* `SelectedProjection.forest_complete` constructs its own finite projection under the selected `ForestClosed` domain. Unselected ordinary roots can remain open. The cap offset is `depth - (path.length - 1)` because the first forest index selects a root.
* `MixedTarget.fold`/`target_reads`, `MixedShared.force_receipt`/`leaf_receipt`, and MixedEdit/Class/ClassPass verify supplied strict reads. These are actual-return producers of their stated laws. They are not initial completion theorems for those enclosing callers.

## Exact composition gap

`TargetGraph.Fold.cons` runs **head Operand, recursive tail Fold, then checked query**. Each Operand projects the immutable captured forest at the current heap and then performs the actual allocated Merge. The heap, Merge table, global memos, and next inventory must join at each literal return.

`TargetComplete.fold_complete` still takes `FoldRanges`. Its first conjunct ranges over an actual earlier Operand return. Its second conjunct requires WordRanges at an actual earlier Operand plus tail return. `target_complete` takes the corresponding `TargetRanges`. `SharedTargetForce.complete` takes `ForceRanges`, which requires that TargetRanges on a miss. The new contiguous native-query program does not discharge any of these range predicates across an Operand's heap mutations.

The proposed Operand proof should establish these local facts before a Target induction:

1. Projection derives its constructor requests, counter increments, and returned heap mass from the initial causal heap bound and finite path. Head exposure, stored Mu winners, and union construction must be included.
2. General Merge derives the same quantities through ordered small rows, large columns, selection comparisons, and recursive calls. `MemoMergeGraph.Run.select` contains a literal completed `SourceMergedSelection.select` execution. It is not a checked TargetQuery Step. A numeric transfer for these comparisons must be proved; the checked native forecast cannot be applied by name alone.
3. On a warm Merge hit, the physical stored entry and initial heap mass bound control its actual result. On a miss, derive the candidate bound from the smaller actual body before publication. A reread can return an earlier winner. Bound that winner from the causal returned store, not from the losing candidate.
4. Reuse the existing Operand receipt for Ready, contextual inventory admission, physical effects, original availability, closed result, global tables, and unchanged native/domain tables. `CurrentNative.advance` and the existing Merge producer retain current joint laws. Rebase the inventory at the actual returned heap with `NativeInventoryRebase.rebase`; keep its captured origins. The native domain component is retained by the Operand receipt, while the next query's domain lookahead must use the larger forecast node counter.

After these lemmas, define the Target forecast in its actual order: forecast the head Operand, forecast the tail from that return, then apply the existing native-query forecast. Check Room at every such query entry from this pure initial schedule. Construct the full Target receipt and strict reads directly. If the old universal TargetRanges interface is also needed, identify arbitrary completed earlier Operand/tail graphs with the constructed returns using literal-worker uniqueness; existence of one constructed return alone does not prove a universal plan.

For Force, reuse the old hit branch with exact state identity. In the miss branch, construct that Target, derive the universal slot certificate from its same reads before `Ready.store`, and retain the exact captured record/forest/path. Leaf then forces first and intersects the actual target with its actual current edit input. The current input is not the captured original.

## Source and outer boundaries

`MixedClass.verified` creates fresh class-local slots for its literal entry forest. `MixedClassPass.fold` is tail-first: the head captures the actual tail result, and the tail receipt transports selected domains. Final empty propagation changes no checked state. A constructive mixed ClassPass will still need head/exposure, edits, Force/Leaf, and constructor resource forecasts; its logical `sizeOf` cap-depth formula is not a reservation budget.

The Haskell gate is not identical to `ForestClosed` or to a whole-forest finite Cap premise. `Operations.hs` partitions classes on the original forest before Require and `foldr` edits. It refuses paths through Rec and InternedUnion and selected constrained-Mu cases. Endpoint-only refusal has a separate `provablyEmpty` query. Unrelated unselected constrained recursive roots can remain in the source input, although a whole-forest finite Cap premise excludes nonhereditary Mu. Do not claim that the present all-root mixed-cap theorem covers every source-approved class. A source adapter must derive the selected masks/caps it actually needs without imposing all-root closure or silently removing refused classes, their equality payloads, or their fourth-table queries.

The outer gap is independent of Target resource admission. `PartialGraph.Rows` runs parent EdgeCall, descendants of the **returned** edge, then the original row suffix. Its child requests use the actual combined and descended inherited payload. `PartialActiveOrder` ranks immutable ordinary height and requires a separate `ReturnedBounds` law; semantic narrowing alone does not imply that law. `OuterResourceDefs.Below` explicitly requires finite-ordinary Domain. The existing quantitative returned-store helpers install a law only after a producer has proved it for the exact captured owner. Empty initialization, warm readback, and finish transport do not supply the missing general producer.

The live Haskell comment already records the obstruction: unequal path lengths can move a constrained node into an unconstrained recursive unfolding at greater depth. It gives a fixed historical refused-cycle repro, not a new defect. Neither a finite guard Cap nor a computed native instruction bound proves general outer ActiveAbove descent. Repeated passes and the fixed point remain separate from one pass. The Merge graph also explicitly models completed sequential calls, not Haskell lazy publication, pending ancestors, concurrency, or runtime forcing.

This integration would test the next constructive boundary. It would not establish general outer completion. This survey ran no new Haskell experiment and reports no new Haskell defect.
