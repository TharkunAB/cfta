# Draft next frontier after admitted cached fold completion

DRAFT ONLY. The current completion interface is selected prospective data. This report does not claim that its proof or checks have passed. It selects no future mathematical interface or runtime representation.

The nearest substantive bridge is incoming-node cache completion at the actual write-and-inherit endpoint. `IncomingNode.run_complete` already derives its representative read, compression Frame, raw execution, actual write prefix, after-write storage/realization, returned Post/query tables, and decoded replacement. Feed that derived prefix into `NativeIndex.gained_complete`. This yields a finite native gained-only update, canonical counts at current roots, native flags at the reached heap, and a cache framed onto the same after-write core. Do not ask a caller for a successful callback, desired prefix, or final cache.

The compression Frame preserves values/counter and exact root paths. Thus the fold cache can be framed onto the actual read core; counts and old flags retain their values, and Roots transfers through Frame.reaches. Returned Post effects supply heap Keeps. The incoming write retains the old suspended bucket and prepends incomingScs, so native gained=incomingScs/lost=[] matches the existing canonical gained law. `NativeIndex.count_complete` already counts every occurrence through the actual read-only representative. Reuse it rather than prove another count identity.

A runtime representation gap remains. `IncomingNode.run` returns the earlier read endpoint. On replacement Empty, it has already written the target and inherited ancestry, then returns raw `[]`. That raw list contains neither the new handle nor after-write core. A raw-row-only cache adapter cannot recover the post-write cache from that result alone. Any executable bridge must retain the actual internal write evidence independently, or state an explicit unavailable-cache boundary. The logical producer already supplies this evidence, so no successful prefix premise is justified. Runtime faults and codec none must retain their actual Caller/query/read observations.

Terminal-prefix cache packaging is smaller but also necessary. `TerminalPrefix.run_complete` computes recorded roots in original order, unions original variable IDs, derives winner and ascending distinct nonwinner keys, and transfers waiting counts. Its values stay unchanged, so old native expandable flags stay valid; however waiting changes to the computed moved map. Plain `frame` alone cannot represent that transfer. Preserve that actual moved map and mergedRoots count view, then use the selected cached-fold completion at the same joined endpoint. A fold rejection must abort incoming handling and retain its reached heap/cache. Incoming Empty rejects before the terminal prefix; incoming replacement Empty rejects after write/inherit. The terminal returns a winner hole; later wrapper finalization writes the returned fragment at captured original uv′.

Do not infer the terminal domain from ordinary cache invariants. Prefix completion still requires genuine Safe, InputsPending, and suspended-variable bounds. CachedChild/Prepare/Stages export storage, realization, Roots, counts, flags, and fragment bounds, but not Safe or global live-root laws. CachedPrepare covers actual nonterminal children; captured unsupported actions in CachedStages remain an explicit stop, not a terminal execution or native rejection. Extending that case requires correspondence to the actual terminal path, not a presumed fallback result.

Initial-only mixed numeric admission remains separate. Keep genuine fold and incoming request ranges explicit in any intermediate terminal result. The existing Frame/Fits query and fourth-call numeric producers are available; they still need same-endpoint mixed-loop threading. H6 remains the strongest proved result, and the full driver goal remains open.
