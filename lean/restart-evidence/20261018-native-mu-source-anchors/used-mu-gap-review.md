# Retained used-Mu source alignment

This is a read-only source review. It adds no Lean theorem or executed example.

`NativeMuPublication.History.from_empty` already extracts the actual earlier first writer of each present Mu. `Written` retains the exact source expression, fixed captures, three completed callbacks, their exact states, actual reservation, missing payload before publication, and callback subhistories. A warm hit can retain an older writer. It cannot be identified with the current candidate without an additional proof. See NativeMuPublication:21-54, 276-283, 330-335. Plain History.retain records NoNewMu, not Grows. NativeMuGrowthWriters.from_empty and Written.raw_callbacks supply the stronger chronological growth when an actual Path is available.

`NativeNormalizedComparisonExecution.history_unused` is specifically guarded by usesLocal=false (:417-423). Its private MuLaw has that same premise (:29-31). The proof carries this law through actual histories and uses the smaller body comparison for each candidate. It supplies no used-local law.

Pair occurrence and retained deep use are different tests. `SourceRecursiveIntersectionMaybeMu.maybeMu` calls construct if the pair is in body.free (:33-37). The callback can then remove that pair from root alternatives. An actual pair-used call can therefore return an ordinary row. The new ordinary-return source anchors cover this case. They do not by themselves cover epsilon exposure of a retained, genuinely used Mu.

Dropping the unused premise from history_unused is false. Source syntax `binder true (node [mk 9 () [var 0]])` retains a Mu: its body contains its own interned reference below a node. cleanup retains that Mu because the self name is free and the body is not the bare self reference (InternedConstructorTemplates:631-635). Its ordinary probe has an ordinary node root; eraseSelf leaves that node unchanged (NativeCallbackErasure:25-27). The two root constructor tags differ. This is a source-inspection counterargument to an overstrong exact readback equation. No new executable or kernel theorem is claimed here. It does not refute observational reconstruction alignment, and it is not a Haskell defect. Haskell dropRedundantMu and callback root filtering have the corresponding branches (Interned/Type.hs:691-698, 735-753).

The strongest existing publication reconstruction theorem found is `NativePublicationNodeAlignment.publication_node` (:52-73). It requires a node source root, strict child Aligned premises, a common ready Keeps endpoint, and an available replacement. It constructs both sequential reconstructions and exact common-reader replays and derives Related. The static binder_free endpoint discharges the children for BinderFree syntax (:198-226). `StoredMuRetainedAlignment.publication_rows` (:207-229) covers arbitrary nested children, but proves paired physical Empty decisions and row survival only. It does not compare nonempty reconstructed children or opaque Mu atoms.

The next causal theorem must remove the node-root and supplied child-alignment restrictions by induction on actual publication history and source syntax. For each actual selected first writer, it must align execute(event.body, self-to-replacement) with execute(event.ordinary, ordinary-to-same-replacement), retaining complete actual call states and a produced recursive row/plan correspondence. Fresh candidates use a smaller-body argument. Older winners use an earlier publication argument. Entry identity alone is not a chronological rank: an outer entry is reserved before an inner entry can finish. The same current key and coherent complete ordinary payload can then connect the selected historical ordinary probe to the current call's ordinary probe.

Related alone is insufficient for exact row ancestry. It retains physical Empty agreement and finite open observations, but it does not state a literal indexed full-guard/ordered-child call correspondence. A usable stronger endpoint must retain that correspondence or derive it from a produced source-plan relation. StoredLiteralRowLineage.execute_row already derives exact fields and actual ordered child Calls within ONE stored reconstruction, including nested Mu and union normalization (:199-261). It does not identify two distinct historical reconstructed bodies merely from matching Mu keys.

There are two further source levels. The new Mu source anchor belongs to the actual generated native child body, which may itself be a generated query result. An initial QUERY operand anchor cannot preserve one operand's full guard globally. Ordinary native compilation combines a paired original left/right row with the actual allocated conjunction and ordered child pair queries. NativeQueryRowOrigins.rows_writer retains those paired indices and historical edge writer (:177-205). Thus the next query ancestry relation needs paired operand row occurrences, the actual conjunction derivation, and ordered child pair traces. Mu rebinding preserves full fields only inside the selected generated body. This review does not conflate these statements.

The proposed integration uses the existing closed Mu and union native fixtures against QueryMuSourceRows.request. Those fixtures do not establish pair-used execution; the Mu source body has no recursive occurrence. A possible genuinely pair-used query uses distinct outer Mu unions containing unused raw inner Mu wrappers that capture the outer self, plus a common leaf. Their inner query can expose the enclosing repeated pair as a bare root; the outer union can then contain that pair and the leaf. This is a candidate only until an actual execution is checked. No infinite trace, divergence, or universal termination claim follows.
