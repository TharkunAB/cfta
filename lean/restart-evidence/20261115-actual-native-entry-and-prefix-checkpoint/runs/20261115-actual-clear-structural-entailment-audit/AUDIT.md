# Actual clear and stored fragment equations

Status: source audit. The optional obstruction candidate is UNCOMPILED.

Stored expanded-fragment equations and UF do not entail every removed `Holds`
equation. The actual consecutive producer leaves the cleared owner pending.
The existing structural assignment theorem preserves arbitrary UF-compatible
terms at every pending owner. A finite leaf at that owner violates any removed
represented proper path.

This conclusion is conditional on an actual removed bucket containing such a
path. This packet does not exhibit an accepted-source execution with that
bucket. It does not prove that an accepted output has no correct completion.
It identifies a limitation of the proposed structural entailment argument.

## Exact actual producer

The producer is
`SourcePruningEnumerationSharedBucketWriteToClear.written_bucket_removed_after_finalize_callback`.
Its hypotheses are consecutive observations of these actual functions:

1. `SourcePruningEnumerationSharedIncomingNode.run` writes the incoming bucket.
2. `SourcePruningEnumerationFinalize.run` finalizes `parentTarget` with `fragment`.
3. `SourcePruningRecordTypes.recordTypes` returns the literal false callback row.
4. `SourcePruningEnumerationRestart.decision` selects the held target.
5. `SourcePruningEnumerationSelectedStep.runPrefix` reaches its literal
   parked singleton row and the stated continuation.

The theorem retains all indexed entries of `incomingScs ++ oldScs`. It proves
that `parentTarget` differs from the cleared representative. It identifies the
same native handle before and after the clear. It proves that `checked` is the
resolved state with that representative set to `.unenumerated (some handle) []`.
The earlier stored bucket gives the index bound for this write. The final
lookup therefore remains pending with an empty bucket.

`SharedSelectedOpaqueDispatch.finalized_core_of_run` identifies the only stored
fragment write in this segment. It writes the different `parentTarget`.
`SourcePruningRecordTypes.recordTypes_frame` preserves the value table and UF
classes through the callback. These facts preserve identities and storage.
They do not create a stored expanded fragment for the cleared owner.

The producer also preserves the UF class of every raw removed RHS variable.
Class preservation says which term each RHS variable must denote. It does not
relate that term to a proper subtree of the still-pending owner.

The exact source header is preserved in `PUBLIC-HEADERS.txt`.

## Existing structural completion theorem

`EnumerationPendingAssignment.stratified_extend_pending` takes
`EnumerationSchedule.Safe state`, `EnumerationOrder.Stratified state level frontier`,
and any UF-compatible `base`. It returns one assignment which satisfies UF and
all stored expanded-fragment equations. At every pending owner, that assignment
equals `base`.

`SourcePruningEnumerationPartialOutput.rootPartial_complete_pending_choices`
already combines this theorem with the actual same-root partial readback. The
same freedom in pending choices remains in its conclusion. Its
`StoredEquations` predicate contains UF and fragment equations only.

The audit searched the live source for the literal name `ConstructiveSafe`.
That name does not occur. The obstruction uses the precise public inputs
`EnumerationSchedule.Safe` and `EnumerationOrder.Stratified`. It does not assume
that the consecutive receipt alone proves these endpoint inputs.

## Conditional non-entailment

Assume the post-clear state is safe and stratified. Let `owner` still be pending.
Suppose a removed `sc` represents `path`, where `path ≠ []`.

Use the constant base assignment `fun _ => Term.node leaf []`. It is
UF-compatible. Apply `stratified_extend_pending`. The resulting assignment
satisfies every stored expanded-fragment equation and UF. It assigns that leaf
to `owner`. The lookup of any proper path in the leaf is `none`. It therefore
cannot equal `some (assignment sc.var)`.

The exact candidate theorem and its complete proposed proof are in
`OBSTRUCTION.lean.txt`. The file is UNCOMPILED. Its logical argument uses the
already existing completion theorem; it adds no model provider or native
membership premise.

The distinction in quantifiers is essential. The candidate establishes a
structural assignment which violates the removed obligation. It does not
establish that every structural assignment violates it. The full goal asks for
one assignment which satisfies all requirements together.

## One concrete path

Take one removed entry whose represented path is `[1]` and whose raw RHS
variable is `r`. Let the cleared representative be `h`. Its required equation is

```text
(rho h).atPath [1] = some (rho r).
```

For the structural extension of the constant leaf base, `rho h = A[]`.
The left side is `none`; the right side is `some (rho r)`. The equation fails.
This remains true if a different expanded parent contains a hole for `h`: the
evaluator fills the parent with `A[]`, so its stored equation still holds.

This is a path example under the actual receipt's pending-owner conclusion.
It is not a claim that a particular accepted source branch has this bucket.
It does not use an independently chosen `TypeIn` witness or splice local models.
No native-domain or residual claim is made for the leaf base.

- `SourcePruningEnumerationRecursion.clear_satisfies` gives the exact equation:
  pre-clear `Satisfies` is equivalent to post-clear `Satisfies` plus all removed
  `Suspended.Holds` equations under the same assignment. The extra conjunct is
  present in the existing theorem. It cannot be discarded by structural UF
  completion.
- `EnumerationState.suspended_descent_complete` reconstructs arbitrary proper
  paths from arity, terminal equalities, and child `Holds`. The equivalent
  `EnumerationCPSDescent.suspended_decomposition` covers the actual batched
  bucket operation. Both require the missing child obligations. Neither derives
  them from UF and stored fragments at a pending owner.
- `EnumerationPendingAgreement.stored_bucket_holds_transfer` transfers an

  at all pending owners. It requires the witness in its hypothesis. It cannot
  create it after the bucket has been cleared.
- `SourcePruningEnumerationSharedSelectedOpaqueDispatch.stable_complete_sound_retained_resources`
  derives the inherited constraints for the actual retained completion case
  from a full post-state `Satisfies` premise. That theorem has an explicit
  `retained` hypothesis. It does not fill the parked pending-owner gap.
- `SourcePruningEnumerationPrefixFreeArrowBucketWitness.selected_prefix_free_arrow_bucket_assignment`
  supplies one whole-bucket local type witness. Its conclusion does not include

- `strict_prefix_alias_no_bucket_assignment` in the same module rules out a
  finite bucket assignment when UF-identical targets occur at strictly nested

## Exact missing relation

For each actual removed receipt on the same emitted output branch, the final
single assignment must satisfy

```text
for each raw sc in the receipt's exact removed bucket,
for each path in EqualityTrie.fromPathTrie sc.trie,
  (assignment clearedRepresentative).atPath path = some (assignment sc.var).
```

The proof must derive this relation together with the original native domains,
UF aliases, stored equations, residuals and same-root completion. It must retain
the raw targets of every historical occurrence. Equal recursion keys are
insufficient: `EnumerationState.recursionKey` retains the node and trie shapes
and deliberately omits equality-variable identities.

For an expanded owner, the existing descent lemmas indicate the required
connection: the actual selected edge and its actual child continuation must
relate every represented path to the same assignment at the corresponding
descended target. The child `Holds` premises then reconstruct the parent
obligations for arbitrary paths.

At this parked owner there is no stored owner fragment to supply that
connection. The exact operational `continueWith` / `resumeWithChild` equality
does not supply a semantic path relation. A proof must construct compatible
pending choices for all such historical path constraints together, or derive
an equivalent relation from the actual source continuation and its raw target
correspondence. That construction belongs in the proof. Adding it as a new
original caller premise or a semantic provider would not close the goal.
