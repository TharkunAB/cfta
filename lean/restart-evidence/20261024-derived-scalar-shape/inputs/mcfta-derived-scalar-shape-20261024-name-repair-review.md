# Trailing-hash generated-name repair review

Reviewed at 2026-10-24 03:37:35 CEST. Status: **MINIMAL_REPAIR_SCOPE_CLEAR**. The retained constructor probe establishes a concrete producer defect. Rejecting trailing-`#` base names in the shared naming function is the smallest repair that preserves the documented naming rule. I read the complete 73-line current implementation, both complete native probe sources, both logs and their report. I did not compile, execute Haskell, edit repository files or mutate Git.

The control declares `data Hashy = Constructor` and calls `deriveNode ''Hashy`; its recorded Nix/GHC 9.14.1 check exits zero with an empty log. The otherwise equivalent MagicHash module declares `data Hashy = Constructor#`; its recorded check exits one with GHC-55017, `Illegal data constructor name: ‘Constructor#Node’`. Its source declaration passes the frontend and reaches TH declaration checking. All recorded source hashes, raw hashes and raw byte counts match the retained files. This is an isolated generated-name failure, not evidence of a typing, rank, pruning or core automaton defect.

`generatedName` at TH.hs65–73 checks only the first character with `isUpper`. It then appends `Node`, performs a namespace lookup and calls `mkName`. A legal uppercase base ending in `#` passes the first check, but appending `Node` places the hash before alphabetic characters. Lookup does not establish that the new spelling is a legal declaration name. The function is shared: TH.hs46 supplies `lookupTypeName` for the view type; TH.hs56 supplies `lookupValueName` for each view constructor. The same spelling defect therefore applies to both call sites. The retained directory currently contains only the constructor probe and its control; Root's planned native type-name reproduction remains pending, and this review does not invent its outcome.

The repair should test the base-name trailing suffix **inside the existing uppercase-name branch and before either namespace lookup**. A small `isSuffixOf "#"` test is sufficient; it comes from `base` and requires no package dependency. Route failure through the existing `unsupported` function with an explicit feature such as `names ending in #`, giving the established manual-node-view diagnostic. Preserve the original source name in that diagnostic context. This is a lexical suffix rule; do not reject every module that enables MagicHash. Keep the current symbolic-name check and all accepted ordinary names unchanged. Preserve constructor traversal and the earlier source-form/context/type-name checks.

Do not strip or move the hash, append additional hashes, or invent a different suffix. Those alternatives change the documented `nameBase ++ "Node"` rule and can change name collisions. For this small repair, a complete identifier lexer, new name type, callback or general validation framework is unnecessary. The initial character and trailing-hash restrictions are checks on reified legal source names, not a claimed lexical validator for arbitrary strings.

Regression coverage can stay in the existing `Spec.hs` rejection example. Add a legal trailing-hash source **type** and a separate ordinary source type with a trailing-hash **constructor**, with MagicHash enabled.
