# Selected stored-Mu readback audit

Reviewed on 2026-10-19. The audit led to SourceCurrentStoredMuUnfoldChildContexts. No old source or frozen evidence was changed.

## Existing boundaries

NativeMuPublication.History.writers returns an initial record or an exact earlier Written publication. History.from_empty excludes the initial-record arm. Written retains the actual expression, captures, three callbacks and first-write fact. It does not retain a writer-to-reader growth or issued-name suffix. History.retain requires only NoNewMu. Thus a publication History is not an issued Path or a general growth theorem. Actual operations can supply those facts separately.

NativeOriginExposure.unfold_origin derives a successful stored-body execution from a complete Mu epsilon Origin and Valid at that view. Its remaining Origin stays at the original view. It is not a literal row of the returned value and cannot be moved to the return heap by growth alone. NativeOriginViewBranches keeps the captured checked writer separate from that physical view.

StoredMuRowOrigins.mu and StoredMuLiteralRows.mu invert actual open-Mu reconstruction. A literal output row forces smart cleanup to return an unused winner. They derive the original body's actual call under the current ordinary local name. Closed Mu reconstruction has no literal row. NativeBinderReaderRows and NativeConstructSourceRows already handle the corresponding actual ordinary return; they must not be restated as retained-Mu observation theorems.

StoredLiteralRowLineage.execute_row and source_row retain a RowAt anchor, full symbol, full guard, arity and ordered Calls. Their public Origin intentionally drops the semantic state at each selected child call. StoredLiteralCalls.indexed can recover that state only when the row-call entry already has SemanticHeap, Values and Replacements. The new module derives these facts from the actual source prefixes instead of supplying them as an output premise.

StoredMuChildLineage proves independent-source equality. StoredMuActiveChildLineage requires conditional source induction hypotheses. StoredMuBinderChildLineage extends paired lexical inputs at real publications. None already derives the new single-output supported child cut.

## New proved literal-row producer

For the exact stored M = mu entry body depth ordinary, unfold_child takes SemanticHeap before, Available before M, the actual completed unfold, a literal row of its return, its exact child index, History empty reader and Grows unfoldAfter reader. It needs no Ready, issued Path, future completion, paired output law or current compiler body.

It derives Written empty entry.key M and Child body before unfoldAfter row index child. Child retains an original RowAt body row, full fields, arity, the indexed original child and its strict structural size bound. The changed-child arm retains the exact lexical execute, SemanticHeap, Available and Replacements at its real entry. It also retains growth and issued extension from the unfold entry to that cut and from the child return to the unfold return. The identity arm does not invent a child execution in a closed shortcut. No bound is placed on a reconstructed child.

The nested-used fixture constructs mu x. outer[mu y. inner[x,y]]. Actual unfolding changes the nested child. It derives the histories, rejects the identity arm using the unique original row, and extracts the supported changed-child call. This is an actual literal-row example, not general epsilon readback.

## False shortcuts and the next consumer

The existing retained-directed-kernels witness builds a used mu x. node7[x], then calls a different requester whose body is union[node7[x],Empty]. The warm request returns the earlier same Mu. This checked witness refutes an inference from a selected writer to equality of writer and requester source syntax. The new producer names the selected stored body only.

The remaining real extension is an actual observer-chain consumer. RecursiveHeadChainRows.actual already derives a chronological Chain to an ordinary terminal record and exact selected row. A small proposed Chain induction can classify that row as a literal row of the starting value, or select the last actual Mu call in that same chain whose returned value contains the row literally. Member and advance constructors preserve this classification; a Mu constructor supplies the new last call. Retain the Chain prefix, the actual unfold and the following member/advance suffix. The new unfold_child can then supply the selected stored body's supported child cut. This chain selection is a proposed next theorem, not a proved result in this component.

For an actual Head, the existing consumer needs its explicit Ready, Available and closedness premises. Its physical publication prefix must still come from actual histories. Do not infer these premises from arbitrary epsilon Origin. The chain consumer would not identify a stored callback with a current native body, give source ancestry through an interned backedge, bound a generated child, or supply a whole-event projection. Those obligations remain separate.

NativeMuIssuedWriters.raw_contexts and CausalStoredMuGenerators.selected remain stronger alternatives when an actual issued Path is available. They cannot be invoked from the new publication History alone. Their whole historical lexical contexts include unused captures, so replacing their Path with bare Grows would lose a real premise.
