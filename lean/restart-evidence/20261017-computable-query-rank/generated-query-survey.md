## Existing composition

`CheckedJointInventoryQuery.generated_complete bits depth F S inventory before good current semantic context stored origins scopedCache idle left right leftAvailable rightAvailable leftClosed rightClosed leftCap rightCap nodes edges room` constructs `∃ fuel value after, Receipt next depth F S fuel left right before value after`. Here `next.source` is the literal entry heap and `next.roots` is the old roots followed by the two actual operands. No `WordRanges`, completed trace, or result law is supplied (119–161).

Its entry inequalities are exactly `heap.nodes.next < 2^bits`, `heap.edges.next ≤ 2^(bits+2)`, and `domains.next + 2^(heap.nodes.next + heap.nodes.next*heap.nodes.next) < 2^(bits+1)`. `RecursiveWarmInitialRanges.warm_initial_ranges` derives all reached word checks from these entry facts. It accepts the populated native and equality tables unchanged (26–54).

The joint receipt extends the covered/contextual physical receipt. It retains the same checked trace and exact interpreter return, available closed result, exact intersection language, scoped and idle native cache, semantic readiness, contextual interpretation, and all-cell admission. It adds `KernelJoint.Context Plain`, joint cap/classifier stores, captured origins, `Cap Plain depth result`, `Classified`, `Original`, and `ProbeFree`. `Receipt.inventoryAt` provides the next `InventoryState.At` directly (31–62). These are actual-return facts, rather than a desired output premise.

`InventoryRebase.rebase F S inventory before good current left right available available closed closed` rebases the contextual interpretation and admission before the next query. `CheckedJointRebase.rebase annotation source state sourceFacts growth history physical origins jointStored` returns the joint store and origins indexed by the current heap. Origins cover suspended, evaluating, and returned cells. They retain complete original operands, bindings, and seen-pair read witnesses. The rebase does not infer a stronger conditional law from an old vacuous law.

The cold bootstrap is `CheckedJointInventoryCold.cold_complete`: initial empty native cells, legitimate physical `Good`, semantic readiness, causal `GuardHeap Plain`, original available closed cap inputs, and the same numeric entry inequalities produce the concrete-inventory joint receipt. Arbitrary warm caches do not follow from physical `Good` alone. Their contextual, joint, admission, scope, and origin laws must come from actual earlier receipts.

## Numeric wrapper

Let `T = NativeComputedBudget.instructionBound N E S`, `C = MassTrace.credit T S`, and `M = MassTrace.massAfter T S`. Define the next forecast as `(N+C, E+C, D+T, M)`.

`NativeComputedBudget.initial bits holds before good semantic idle left right original original available available closed closed stored nodes edges room` constructs its own physical receipt at the same query entry. Its outputs include actual `fuel ≤ T_entry`, literal `execute (T_entry+1) = done value after`, `Stored (massAfter T_entry S) after.heap`, result mass, both constructor counters bounded by entry plus `credit T_entry S`, and domain count bounded by entry plus `T_entry` (61–113). Here `T_entry` uses the actual entry node/edge counters and the supplied causal `Stored S`; it does not recompute an uncontrolled later `initialBound`.

The smallest wrapper can construct both `generated_complete` and `NativeComputedBudget.initial`, then apply `TargetQuery.Step.unique` to their own physical traces. This proves equality of the result and the entire checked state, including operations and both populated native tables (48–55). It transfers the numeric conclusions to the semantic/joint receipt. No other completed graph is a public input. A direct alternative uses `InstructionTrace.node_prefix` and `WidthTrace.prefix_bound` on the generated receipt's own trace, then applies `nodeBudget_le` and mass/credit monotonicity. The second route avoids the auxiliary constructed execution.

`instructionBound_mono`, `MassMonotone.massAfter_mono`, and `credit_mono` replace actual entry counters and actual trace count by `N,E,S,T`. The forecast therefore gives `Stored M`, `N_after ≤ N+C`, `E_after ≤ E+C`, and `D_after ≤ D+T` at the exact same return. `massAfter_add` and `credit_add` compose at the exact common mass bound. They do not identify arbitrary request partitions with one fixed instruction schedule.

For a finite result-fed schedule, iterate the forecast using only initial numbers. At every query index `i`, require the computable forecast inequalities:

```
N_i < 2^bits
E_i ≤ 2^(bits+2)
D_i + 2^(N_i + N_i*N_i) < 2^(bits+1)
```

All three are initial forecast conditions. No later actual counter is an assumption. Monotonicity derives the actual next-entry inequalities. In particular, `D_i+T_i` is the returned domain forecast. It is not by itself the next query's domain-admission lookahead. Using the existing completion API still requires the exponential inventory term above. A smaller instruction-only domain admission bound would need another range proof.

The serial induction must retain the inventory receipt, current-heap joint invariants, `Stored S_i`, idle/scoped native cells, and available closed cap operands. A returned value supplies the next operand's availability, closedness, original syntax, probe freedom, and same-depth cap. Previously retained operands remain available by the exact extension. Query results may be chosen by the schedule, but their required source properties must be derived from those actual receipts. A schedule callback cannot assume successful future queries or their counters.

Full caller integration also needs `ClassScan.Ready` and global memo validity. `TargetQuery.finite` already derives both at its exact return (58–100). `Step.verified` aligns these with a supplied actual step. The joint inventory receipt alone does not expose the full `Ready` and global-table bundle. Reuse that actual trace-effects route or `Step.verified`; do not silently strengthen its receipt. `CurrentNative.step` provides current-heap joint stores and the returned cap for the same actual target step.

## Scope and remaining obligations

`StaticQueries.complete_many` already constructs any finite list of original-source operand pairs with one original domain reservation. Its inputs explicitly require every pair to be available in that fixed source (126–171). It cannot admit the new singleton result described above. Extending that theorem by dropping its original-source premise would be unsound.

The new wrapper and finite forecast induction are not implemented by this survey. Initial physical/semantic readiness, causal guard heap and warm cell laws, closed available finite-depth cap operands, and the forecast capacity conditions remain legitimate entry assumptions. They can be derived from existing actual source construction/preparation in a dedicated initial-source endpoint. This query composition does not prove a general constrained outer reduction, selected descent, convergence, or total runtime/memory cost of all global/native/equality tables. No Haskell source was changed and no runtime defect was found.
