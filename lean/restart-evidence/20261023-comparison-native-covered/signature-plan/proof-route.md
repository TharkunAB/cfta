# Proposed proof route

This package contains declarations and local types only. It contains no proof body.
1. Start the future body with `classical`. Count this one line in the source estimate. It supplies the existential case split. It adds no public premise. Reduce only the public result lets.
2. Define the three exact local lets. Invoke H15 once with the fixed finite model and ranks. Keep its fuel, result, full after state, done equation and twelve outputs.
3. Prove finalCovered by the exact published-key case split. On a hit, apply H27 to the same done equation. Transport incoming Covered through equality of the full checked states.
4. On a miss, derive both absent keys by Option cases and the negative published-key proposition. Keep the actual complete Edge records.
5. Use H18 on both admitted closed original parents to obtain the exact child Original and admission facts. Derive source residency from literal row membership and Facts. Transport residency through the incoming growth.
6. Build raw scope and coverage. Split only on the canonical strict identity comparison. Swap both complete operands and their scope/admission facts together. The request is emptyDomain; other source bindings may be nonempty.
7. Derive current readiness and literal edgeBody Fields. Derive Resources from the initial global Room and initialValid. Construct Current with the same incoming allocation Trace, growth and issued history. Do not reset the initial cache.
8. Build the physical and admission certificates from public APIs. Apply miss_readback to the SAME H15 done. Feed its raw Steps to prefixes and obtain a physical Receipt at the same endpoints. Raw Steps alone do not imply a physical Trace.
9. Apply Trace.covered with branches, the physicalRun.trace and incoming Covered. Return the original H15 witness and all twelve outputs, followed by this derived native Covered.

The H15 and miss result files specify the destructured types. The insertion map fixes all let/have/cases/obtain fragments and their lexical order. Lambda and intro fields are listed in branch-and-destructured-types.json. No additional typed fragment, helper or induction is authorized.
