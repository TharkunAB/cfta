# Resource boundary

The current public Room predicate contains source.nodes.next, source.edges.next and an exponential function of source.nodes.next. The H23 output has growth and an old-source allocation Trace, but no corresponding upper bound for the new heap source profile. Source growth is the wrong direction for deriving stronger Room at the same width.

A new-inventory trace can be obtained only after a genuine inventory inclusion/history argument. The inspected Trace API has trans and numeric bounds at one fixed inventory. It does not expose a general inventory-reindexing theorem. A small reindexing lemma alone would not produce the larger numeric reserve.

A substantive later capacity proof must account for all actual comparisons and the final makeNode allocation before width selection. It must retain the same populated caches, old initial domain history and actual returned heap. No concrete capacity bound is proposed in this inventory.
