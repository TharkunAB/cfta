The proposed constructors follow the existing runtime equations. These are design clauses only. No new definitions or theorem proofs are present.

Outer HookResult clauses

- None, done, stuck, and depth-zero expand have the exact existing full result and no dispatch events. Keep actual outputs and the actual optional endpoint.
- A parked prefix with no output has the actual empty complete result. A parked singleton uses its actual updated metadata, frame core, and supplied next decision. Recurse at outer depth n while constructing n+1. Keep workFuel unchanged. The actual prefix equation is part of the constructor. It is not a semantic supplier.
- A narrowed empty action or true callback retains the actual complete result and no child events. A malformed, unsupported, or failed prefix retains its exact stopped result. These branches do not run preparation or a hypothetical callback.
- A successful false callback followed by ordinary prepared input uses FullCapturedRows on the exact selector list. SelectedPreparation.run is evaluated only as the original runtime equation. Its actual native outcome and raw entry data determine the same advanced caller and cached frame. Failure or malformed preparation adds no child events and retains its actual preparation stop.
- An opaque or terminal prepared input uses the same literal ChildDispatch observer as SharedSelectedOpaqueDispatch.run when that runtime actually dispatches. Empty/rejected and unsupported branches that do not dispatch contribute no fabricated dispatch. Successful singleton plus cache proceeds to the actual Finalize.run, then to the actual recordTypes result. Only its singleton false branch recurses with FullOuter at n using the returned metadata and frame. Its true branch can complete with zero outputs. A finalizer failure or malformed recordTypes result keeps its literal stop and suppresses the recursive suffix.

Task clauses

- Tuple cons delegates to the full child task with the exact point and remaining tail. Do not append a separate tail list here. The literal child continuation already evaluates that tail, and FullTask includes it. This prevents duplicate accounting.
- Tuple nil under a selected frame records one residual event at the actual before/after caches. It then uses FullTask for the exact returned parent tuple. The final result prepends the SAME complete receipt to that parent result, exactly as actual_source_selected_return_run. It is not merely equal at the native endpoint. Recover parent scope and snapshot by eliminating the SAME selected frame ledger; omitted mass/seed/cache data cannot be inferred from Prop indices.
- Tuple nil under a captured frame records one residual event. It uses the actual finalizer and recordTypes equations. Only an actual false callback includes a FullOuter subderivation. Nil is not an identity base: the runtime immediately runs the callback.
- An ordinary child delegates to FullRows on the full edgesOf list. The actual lower-height branch is retained. Any shallow fallback branch uses the literal ChildDispatch below. Under genuine Current, the existing source child-height proof selects the lower branch where required. No fuel substitution is permitted.
- A non-ordinary child records the literal dispatch event containing all five original fuels, caller, enum cache, query memos, observation, and optional cache. Its resource and Seeds facts use the SAME ChildObserver return and event tuple. Singleton success plus Some cache continues with FullTask at the actual child endpoint and strict smaller task.work. Every other raw result follows the actual stopped callback. Do not invent success or an endpoint for None. Pruned empty dispatch results still remain recorded.

Row scan clauses, shared shape for the two row families

- Nil has the literal complete [] [] caller queries result and no operations. This identity is valid for scan [], not for tuple [].
- Each row first records the literal CachedOwn.prepare event, including none, empty, multiple, and singleton results. It does not stand for SelectedPreparation.run. None/multiple/empty cases follow the exact receipt consumer. A completed rejection continues to the next row even when it produces no output.
- A singleton own row builds the actual staged.map inputs and actual selected or captured frame. A FullTask tuple subderivation covers its child work and its complete invoked callback. That one full row result supplies the processed receipts and outputs used below.
- If the row result is complete processed outputs reached saved, require FullRows/FullCapturedRows for the suffix at reached/saved, with the SAME captured enum cache. The conclusion concatenates row events before suffix events. It combines processed receipts and outputs exactly as scan_complete. This clause has no outputs-nonempty premise.
- If the row result is stopped processed outputs stop, the conclusion is that exact full stopped result and the row's events. There is no suffix subderivation. Earlier completed rows still precede this row through the enclosing constructors. A stopped callback's events before its stop are already inside its FullTask/FullOuter derivation.

Residual and prepare operations project to no native query events. Finalizer and recordTypes operations also introduce no requestNode event themselves; their exact equations control whether a later callback runs. Native query order is the flatMap of the actual dispatch observers in operation order. The existing native_query_origin then recovers operation occurrence and local index from one global list lookup. Identical tuples and duplicate paths are retained.
