# Exact class dependency through actual descent

The production module has two public laws. `retained` produces an actual child record for every dependent parent class when the source class survives at that child index. `subsumes_iff` proves that two actual retained child records have exactly their parent strict-prefix dependency. The premises describe one well-formed physical payload whose class list is a fixed point of the actual source normalization. Neither law takes a future recursive call, a result rank, or an assumed target-retention equation.

The proof uses the normalized congruence closure. A parent dependency gives one nonempty suffix. Saturation places every source path with that suffix in a component. Disjointness identifies that component with the specified target class. Two distinct source child paths then produce two distinct target child paths. The actual trie test retains that target. The forward implication prepends the selected child index to the two child witness paths.

The first constructed test builds the physical records by `recordOf` and reads their complete ordered payload. Its source class is `[[0,0],[0,1],[1]]`; its dependent class is `[[0,0,0],[0,1,0],[1,0]]`. The parent dependency uses the paths `[1]` and `[1,0]`, outside the selected index zero. The theorem produces the retained dependent child at index zero. It also proves positive retained paths in both actual child records. The second test builds the dependent class `[[0,2],[0,3],[1,0]]`. Both records are well formed and consistent. Both actual child records survive, but their dependency is absent. This also proves that this payload is not a normalization fixed point. Saturation is a necessary hypothesis for the reverse implication in this generality.

This result concerns classes in the same payload. The actual source precheck orders the original own records; inherited combination is a separate operation. The theorem does not rank class occurrences from different source fields. The existing ParentHeightGrowth example transports a different inner constraint through a plain recursive branch. A global progress proof still needs causal occurrence origins, strict consumption of an enclosing phase, and compatibility with complete physical aliases. No outer busy exclusion or full outer termination theorem follows from this module alone.
