# Local finite-cap native compiler review

The four owned modules provide local source-binding and compiler certificates. They do not prove general recursive native completion or a full `compileNode` cap producer. No older production file changed.

`SourceCurrentConstrainedCapNativeScope.lean` uses the existing local `HereditaryNativeScope.Bindings`. A Mu cap at any depth implies the existing hereditary annotation. `bindings_annotated`, `extend`, and `enter` use this fact only for the actual Mu operands that add bindings. `enter` retains the exact allocated domain key. `read` uses the actual source record, source availability, coherent current facts, and both heap and issued-map growth. It does not assume an annotated whole heap. `body_cap` retains the cap of each actual body projection. `edge_child` derives depth minus one for the exact zipped child pair, with hereditary children at zero.

`SourceCurrentConstrainedCapNativeCode.lean` defines an actual CPS certificate over the current `Code` interface. It imports the universal `NativeLaws.NodeLaw` and `EdgeLaw`; it does not create its own result-law variant. Each node or edge continuation gets only the law for its actual request and returned value. `request_node` and `request_edge` instantiate that law at the chosen common depth. Literal constructor work derives cap bounds from the actual coherent cache readback. The bind and walk helpers carry actual `Valid`, `Extension`, representation, and physical availability/residency at each earlier return. The abstract representation predicate must still be established by an execution interpreter. Failure branches impose no successful postcondition. Driver finish frames are excluded.

`SourceCurrentConstrainedCapNativeCompile.lean` certifies actual `compileRows` and the left/right union code branches. Rows use the current hash-joined pair list and its actual member law. Every child callback receives its original ordered operands. The final node uses the actual resident returned rows. Union walks request each original member in source order and construct the union from the actual returned values. No recursive body output or final-cap premise appears in these public producers.

`SourceCurrentConstrainedCapNativeEdge.lean` certifies the literal checked children, sentinel, and actual checked body yield. Children use `depth - 1`. A depth-zero row needs the original guard predicate; positive depths do not constrain the root guard. In the accepted body branch, the zero-depth guard proof comes from the actual loaded conjunction and the existing plain-conjunction readback theorem. The mismatch and rejected branches use the literal Top sentinel. Load errors and missing fields cannot satisfy the supplied successful body-yield equation. The code certificate starts at the exact returned native machine; the body equation retains the actual operations state separately. No general body completion is inferred from this certificate.

Strict direct validation uses the absolute source path and `-Dlinter.all=true`. Final logs are empty: Scope attempt 4, Code attempt 3, Compile attempt 1, and Edge attempt 1. Canonical builds succeeded for Scope 1004 jobs, Code/cache batch 1089 jobs, and Compile/Edge batch 1098 jobs. All final sources match their saved direct and final snapshots.

Earlier failures remain preserved. Scope attempt 1 did not create a source file because the setup used a wrong relative path; its missing-file diagnostic remains. Scope attempts 2 and 3 contain the exact failed sources and logs. Attempt 3 incorrectly received an initial success report because a trailing `date` command hid Lean's exit code. The report was corrected before final freeze. The failed canonical Scope source equals attempt 3, SHA256 `40e11640754459cd9cabe09b421c2c7a4cf90a72f068fb18258e81aa3e259128`. Code attempts 1 and 2 failed on isolated import-path setup. Their exact source snapshots and diagnostics remain. The final checks use the canonical imports and verified Lean exit codes.

`cap-producer-public-1.log` contains 22 complete public signatures and axiom reports. `cap-producer-kernels-3.log` contains three complete kernel signatures and axiom reports. The final logs have no warnings, errors, or `sorryAx`. Each standalone source enables all linters and complete explicit/proof/universe/deep-term/full-name output with one million print steps. Only standard axioms occur. The evidence verifier accepts Lean's explicit universe suffix on public declaration names. Its earlier strict name-parser attempt and unfrozen manifest bytes remain as draft evidence.

The empty-rows kernel uses representation `True` and arbitrary recursive callbacks. Its actual interpreter returns Empty and the same machine without calling either callback. The full-guard constructor kernel executes actual nullary edge work and the following node constructor. It derives the actual returned residency/availability and positive cap without an input guard predicate or output-cap assumption. The source-entry kernel combines actual cap-based entry and later readback. Every entered name returns the exact annotated source Mu after legitimate growth.

Mixed Mu optional binding remains outside these four producers. A positive-cap callback result can be nonhereditary, while a Mu constructor is admitted only through a whole hereditary annotation. Thus `body_cap` alone does not justify an arbitrary optionalBinder output. A separate source-normalization or binder proof is required for the general Mu branch. These local certificates also do not prove all request cache laws, whole trace preservation, query admission, finite native execution, selected-path termination, or whole-library Haskell correspondence.
