# Next chronological observation producer

Read-only proposal, 2026-10-19 02:00 CEST. This note does not assert a new theorem.

## Do not reapply the false gate to later forests

The new public node endpoint covers one actual node edit after a Required origin.
The class right fold first completes its tail, then runs its head on the tail's returned forest.
That forest can already contain native positives and generated recursive values.
Neither a false primary receipt nor `RequiredRowOrigins.Origin` between consecutive class forests follows from the original gate.
Adding those as fold induction hypotheses would leave the main caller gap unchanged.

The node source case also retains row fields, not child identity.
It cannot manufacture a completed projection of an earlier forest.
Projection visits other rows as well. Their successful reads must not be assumed merely because one ordinary route exists.
The public node theorem fixes projection entry to the edit-return heap; a later-entry wrapper alone would not solve either issue.

## Smallest proposed producer: exact recursive-value ancestry

Classify the first recursive value reached by an actual projection/read spine before it performs any Head or Mu unfolding.
For this first step, use a value occurrence that follows only literal ordinary row children.
Do not include stored Mu bodies, union-member epsilon steps, or observed unfolding rows in that occurrence relation.

A minimal occurrence has a root case and an ordinary-child case with:

- The canonical parent-row lookup and the exact child position.
- The selected child value, followed by the remaining ordinary-child occurrence.

Its target value must satisfy `RequiredGraph.Recursive`, which means Mu or union.
The original-source alternative must retain this exact value, rather than only its row fields.

The proposed node theorem is schematic:

```text
actual NodeReads + existing initial physical/memo/history premises
+ ordinary-child occurrence of recursiveValue in result
  => same recursiveValue in input through matching child positions
     OR actual leaf/Head event in this edit
        + ordinary-child residual to the same recursiveValue
        + exact selected edit slices and reconstruction intervals
```

This theorem needs no false gate on the edited input.
It follows the literal edit constructors.
A below-edit of an ordinary value returns Empty or an ordinary value, so it does not create a recursive root.
A recursive root is therefore retained at an unselected position or supplied through an actual leaf/Head cut.
Ordinary lifts must retain the same signed child position, raw/canonical row receipts, and selected `Slice` used in the reviewed observation spine.
A Head event retains its recursive body edit. It must not claim the body return equals the exposed input.

The class and fold lifts can then retain the same original forest index.
They compose exact-value occurrences across completed earlier classes, or retain a chronological earlier event with its remaining edits.
They must keep each class's own captured target forest and base heap.
They must not identify those forests with the initial fold forest.

This is a proposed source producer, not a consequence of the existing row-field theorem.
`ClassFoldStructuralOrigins.fold` retains `RowAt` and `RowOrigin`; those facts do not recover exact recursive child values.
No existing public recursive-value occurrence endpoint was found in the inspected class/edit lineage modules.

## Why this would help the actual reader

`ProjectionReadSpine` records the selected ordinary prefix and the first recursive Head, or a terminal root read that can unfold Mu.
Its ordinary prefix can identify the recursive value occurrence before that first epsilon step.
The proposed producer would send that value either to an unchanged original value or to a real earlier event.

On an unchanged original branch, the original false gate can supply the local plain-region fact at the matching requested child path.
Required preparation must still be handled by its existing ordered origin relation.
The causal guard heap and actual projection/read effects are still needed to exclude a selected nonplain row from that plain branch.
This composition needs a proof; exact-value ancestry alone does not establish the exclusion theorem.

On an event branch, keep the actual remaining edit/projection/read continuation.
An earlier event's value need not stay unchanged through later class edits.
Do not replace that continuation by a new read of the unmodified event value.

When the remaining observation is a complete epsilon read of an actual native result, reuse `NativeOriginExposure.returned` or `request` at the actual supported reader.
These endpoints recover the captured writer and retained-Mu unfolding.
A nonempty residual path requires the native ordinary row/child lineage or further actual branch decomposition first.
It is not automatically an epsilon origin of the whole native result.

## Limits

The source-only alternative applies to an unchanged exact recursive value along the ordinary prefix.
It does not explain a generated Head terminal as an original stored body row.
It does not identify the selected native writer's syntax with the current requester.
It does not assert source mass descent for rebuilt children, a global simulation, a finite request bound, or termination.
The finite source/event occurrence proof and its first-recursive-spine consumer remain separate next obligations.

Relevant current endpoints are `ClassObservationSpines.node`, `ProjectionReadSpine.project`, `SharedEditChildLineage.indexed/selected`, `ClassFoldRowOrigins.rebuild`, and `ClassFoldStructuralOrigins.fold`.
The inspected source pins for the first four are retained in `observation-audit-edit-pins.json`.
