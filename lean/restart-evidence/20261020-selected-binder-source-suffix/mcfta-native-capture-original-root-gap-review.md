# Native captures and original-root ancestry: exact remaining gap

Read-only audit at 2026-10-20 17:26 CEST. No source, repository, or Lean artifact was changed. No Lean job or new proof pair was run.

## What the current producers already establish

`NativeSelfCaptureSlots.lookup` preserves the SAME mapped-leaf index. A row-bearing native mapped capture is either the exact closed leaf at that index in the selected stored body, or the COMPLETE selected self Mu replacing its exact own-reference leaf. Every other reference remains literal and cannot have RowAt. `canonical_slot` adds the coherent/available canonical-slot premises; it does not identify an arbitrary occurrence index with the first equal canonical slot.

`SourceCaptureOriginalSlots.original_slot` removes actual callback-reference prefixes. For a reached capture it gives an exact slot of THAT reached root's initial input list. `empty_initial` excludes row-bearing captures when THAT initial list is empty. Thus it applies to an original Fresh build from `[]`. It does not exclude captures after native stored unfolding: its generated root is `encode (leaves body) [] body`, and its initial inputs are `(leaves body).map (input selfEnvironment)`. Those inputs include whole closed values and may include the complete self Mu.

The new `SourceRowTerminalSuffix.terminal_source` is substantive and closes the former source-union suffix gap. From the actual SourceRow and its original Context/Reached it derives a nonunion terminal call, its Context and Reached, and forward physical plus issued growth from that terminal return to the enclosing whole source-call return. A binder terminal's complete local cell can therefore be transported through that DERIVED suffix before calling `SelectedBinderChildResume.selected_body_child_or_prior` at the same whole call. A bare Origin.binder alone still omits that suffix, but it is now recoverable when the actual SourceRow is retained. This is not the next fundamental gap.

`SelectedBinderChildResume` then derives the exact initial complete cell or the selected historical event and raw source callback. The event, full Mu fields, Context, Reached, raw parent row, SourceRow and resumed child Origin remain one tuple. It roots the result in the root supplied by the actual completed build. When that root is generated encode syntax, it does not change it into original program syntax.

## The two native capture arms require different treatment

For a CLOSED mapped leaf, the exact initial slot gives `leaves body[i] = leaf`, `captured = leaf`, and `RowAt leaf row`. `IndexedFirstOrdinaryCut.split` on that SAME body/index/leaf/row already derives either RowAt body row, or a first ordinary parent row/child cut in body with exact leaf offsets. It must not be replaced by same-leaf descent through original source-union members; that claim has a checked normalization counterexample.

Once the owner Mu has a writer rooted in the original program build, the existing fixed-event machinery can move that full body row to the historical raw callback using `filter_row`, derive its original SourceRow, retain its terminal suffix, and resume the actual indexed source child or exact stop. No leaf-index preservation through root filtering is needed: transport the SAME FULL ROW, not an assumed same raw leaf list. In the cut arm keep the child's remaining inner-leaf obligation; do not drop it when changing to the original source-child call.

For the FULL-SELF Mu arm, the capture is the SAME owner, not a smaller value. RowAt of that Mu inverts to a row in its stored body. A selected original writer can expose that body's historical raw source, but this step alone is not progress: another native own substitution can return the same full Mu again. Any global proof must relate this neutral/self step to the actual native binding/domain owner, seen-pair state or a guarded child transition. Neither source size nor closedness supplies a decrease here.

## Initial resident owners versus later generated owners

A useful bounded bridge can be proved for an owner already present at the ORIGINAL completed source build return. Its premises can be entirely actual:

- `build program [] empty = done programValue sourceAfter` and its derived empty Context;
- the exact full owner cell in `sourceAfter.nodeRecords`, not an assumed Written/Reached ancestry certificate;
- a literal successful later unfold/encoded build and its actual support;
- the actual selected structural row and capture/terminal receipts derived from that build.

`build_writer` recovers the owner publication rooted in program. The native slot split plus the pure body cut and fixed-event raw callback then give the original-root source row/child route described above. This is a genuine local composition target if a consumer needs it. It must retain the generated execution root and original program root as two different objects. It does NOT cover a Mu that is absent from sourceAfter and is first installed by a later native effect.

That latter case is the REAL general frontier. Existing physical Publication.History and issued Path record the literal event callbacks and their chronology. They do not record which actual native/Head operation generated the encoded root or how that operation's stored body came from earlier original inputs. Rooted Written for the completed encoded call supplies Reached under the ENCODED root. `original_slot` then returns a slot in the generated leaf pool again. Repeating these two facts is not a producer of original program ancestry.

## Smallest missing actual producer

Do not add another wrapper of an assumed original-root Origin. The next useful general producer is an operation-labelled selected-writer predecessor, with the INITIAL-CELL alternative preserved.

For one ACTUAL successful Mu-producing operation, derive either the exact selected cell at its entry, or ONE same first-write event whose rooted build has the actual operation's generated root, actual initial leaf pool and actual parent body. The two required concrete operation forms are:

1. Stored unfold: exact `unfold owner before = done value after`, hence the actual build of `encode (leaves owner.body) [] owner.body` with mapped self inputs. `HeadIssuedHistory.unfold` already shows how Ready plus Available derive the rich generated Context. Retain the parent owner complete cell and its availability at the operation ENTRY.
2. Native optional binder: the exact captured body query and `maybeMu pair bodyValue middle = done value heap` from `NativeMuBodyOrigins.Body`; `SourceRecursiveIntersectionMaybeMu.construct_eq` gives the actual binder root `binder true (encode (leaves bodyValue) [oldPair] bodyValue)` with initial inputs `leaves bodyValue`. Retain the SAME captured query writer, child Trace, entered domain and parent bodyValue at middle.

The extra result must keep the OPERATION/PARENT label attached to the SAME selected publication, including nested publications of that generated build and complete payload equality. A warm prior-cell branch must go backwards through actual earlier operation history, not be assigned the current bodyValue or current callback syntax. Existing construct_eq plus build_writer_or_prior is only the one-call starting point; a wrapper returning that theorem unchanged would not close the missing link.

The substantive missing step is to recover that labelled generating operation for an arbitrary selected LATER owner from the chronological actual native/Head execution. This permits an induction rooted in the original completed source construction. Initial source publications have actual program Reached; later publications refer to actual PRE-OPERATION owners/body inputs. It must handle the exact first writer and retain native checked-state/memo intervals separately from physical heap growth. No desired semantic output law or original-root ancestry is an input premise.

This is a provenance induction target, not yet a global well-founded renewal measure. The full-self edge remains nondecreasing, and native body queries can combine operands. The next rank/progress proof still needs the actual pair/binding guard and a bound on effective renewed constraints. A universal assertion that every generated encode root is a literal source subexpression would be the wrong contract; native construction uses generated rows, captures and binder plans. No checked counterexample to a separately specified global ancestry invariant is claimed by this audit.

## Why existing original-row lineage does not finish it

`StoredLiteralRowLineage.anchor/source_row` gives a literal stored-value RowAt anchor, equal symbol/guard/arity and actual ordered child Calls, or an explicit external replacement. Its source parameter is a VALUE, not original Fresh Syntax plus Reached. RowAt traverses stored union/Mu bodies and stops at ordinary rows; it does not cross an ordinary child to an arbitrary closed leaf.

`StoredMuUnfoldChildContexts.unfold_child` gives the exact stored owner writer and supported original-child execution. `NativeMuWriterSourceRows.returned_mu` and `NativeMuSourceHandoff.returned` retain the same captured native writer/body query and either literal row provenance or an opaque selected Mu publication. Their "original body" is the actual GENERATED bodyValue, not original program syntax. They supply useful edges for the proposed operation-labelled induction; they do not supply the induction's original-root invariant by themselves.

`NativeQueryRowOrigins.RowOrigin` keeps exact forwarding and ordinary joined rows but leaves recursive/union/reference residual branches explicit. `InternedFreshOrdinaryBindingKeys.execute_key/key_member` controls one fixed body's replacements in ONE current cache. Its inventory bound depends on the current nodes.next; it does not bound future allocations or prove finite closure across cache growth.

Therefore no current rowlineage or binding-key endpoint silently supplies the missing original-root link. Current results give the local source/capture/winner routes. The remaining general producer is actual generation provenance for later stored owners, followed by a separate guarded/global progress argument.
