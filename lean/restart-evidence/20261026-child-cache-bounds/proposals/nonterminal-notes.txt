API and scope
CachedPrepare.allocated_mass: allocation appends an empty bucket, so mass is unchanged.
CachedPrepare.singleton_counter_mass: actual prepareChild=some[(fragment,after)] plus
initial before.counter=before.values.length gives counter+1 and exact mass increase
(match input value with node=>scs.length | _=>0).
CachedPrepare.singleton_counter_mass_le: same actual observation gives universal
mass<=before+scs.length. Mu and Union ignore the incoming nonterminal bucket and
store [], so the universal exact +scs.length claim would be false.
ChildDispatch.empty_cached: actual run on Empty returns raw some[] and exactly
Some before at the unchanged Caller/query/core/waiting endpoint.

The singleton observer needs only initial alignment and the literal actual cache
equation. It has no heap coherence, desired endpoint, future resource range,
callback success or native-query success premise. Existing genuine completion
producers can supply its actual cache equation as an output; it is not an added
future-success admission condition. Counter+1 follows the actual allocation and
NativeIndex.write core. Ordinary mass uses allocated_slot at initial alignment,
then existing SuspendedMass.incoming_mass with old bucket [] and incoming scs.
Duplicate suspended entries remain counted in scs.length.

To use it inside the nonterminal ChildDispatch arm, unpack the actual cached
prepareChild match. A successful singleton sidecar uses this exact observer.
The Empty-first arm uses empty_cached; Reference or partiality produces no
claimed successful cache. Terminal fallback is outside this observer's scope.
