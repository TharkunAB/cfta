Proof route:
Canonical depends only on stored value payloads. All IncomingNode.run outcomes retain the original values at the outer read; representative compression and native Caller/Queries changes do not change those values. Actual finish success writes incomingScs++oldScs from the pending slot read by the worker. Initial Canonical supplies ValidSuspended oldScs. Incoming ValidSuspended supplies the other half. EnumerationValidity.set_canonical proves the exact new slot update; ancestry changes do not affect Canonical.

The adapter raw[] branch is essential. It reads the old pending bucket from the actual read core, constructs .unenumerated (some 0) (incomingScs++oldScs), and frames that exact synthetic core after a successful index update. The proof applies set_canonical to this branch directly. It does not equate raw[] with a successful row or ignore the synthetic write. The singleton branch uses the existing adapt_singleton_core theorem. Error rows, longer lists, missing slots, failed index updates and unsupported/native-error branches cannot yield Some after and are excluded only by the literal adapter equation.

The runtime case proof follows the already checked IncomingMass.run_mass/adapt_mass proof structure. It introduces no Context, Safe, availability, ranges, Graph or future success premise. Canonical is not Safe and does not assert native realization, candidate flags, waiting correctness or ancestry safety. In particular, raw-empty rejection receives only a canonical-trie conclusion. All statements concern the actual unchanged bounds and returned cores; no completion producer is executed again.
