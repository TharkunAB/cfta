## What this closes, and what it does not close

For a single class capturing the literal `prepared`, each target slot can be capped using only its actual projected endpoints. This removes the premise `∀ original ∈ captured, Cap Plain depth original` from target construction. The actual selected projection domains still supply output closedness through the existing physical receipt. Finite caps and closedness are separate results; neither is inferred from availability alone.

It does not remove `MixedShared.leaf_receipt`'s separate `inputCap` on the current native leaf input (lines107–127). In `MixedEdit`, the leaf case needs both target and input caps; ordinary and recursive cases currently propagate global caps (MixedEdit lines63–93,106–167). A later monitored observation can run below an edited leaf while its other ordinary children stay opaque. A cap on that later projected endpoint is not a cap on the leaf's whole input. `NativeRequestPositivePositions.call` still requires full caps on BOTH exact operands (lines1138–1153). The original false gate cannot simply be rerun on a changed leaf or on a changed captured forest.

The immediate class obligation is a SAME-execution endpoint-corridor invariant for ALL actual edit paths, not merely a list of finite target slots. Root's overlap decomposition gives a narrower route than a general path-local native theorem. If every current edit leaf path belongs to the monitored set E, its own corridor reaches a finite WHOLE value at that exact leaf. This supplies the full native input cap there. The finite target and input caps then give a finite whole query result by the existing actual cap law. No more general native path-local cap theorem is required for that case. Coverage of all edit paths by E must be proved from the actual selected records; it is not automatic for an arbitrary monitored subset.

The literal compiler supports this route:

* `AllocatedClassEditPlan.compiled_allowed` (lines28–30) proves every callback TOKEN belongs to `record.paths`. This fact alone does not identify its execution position.
* `compiled_disjoint` (lines32–36), `SourceEqualityEditCompiledPaths.build_leaves` (lines66–78), and `SourceEqualityClassEdits.edits` (lines26–28) prove the stronger joint relation: each retained compiled pair is `((natural.map Int.ofNat), natural)` for the SAME `natural ∈ record.paths`. * `AllocatedSharedEditGraph.EditNode` has exactly Leaf, Empty, ordinary reconstruction, and recursive Head cases (lines30–45). Its ordered child scans and row reconstruction retain each index (lines47–70). Head consumes no child index. There is no additional LocalMerge edit leaf. Merge calls run inside target forcing. A minimal structural mask for this induction is therefore justified: for a fixed natural path, either the entire current value has a finite Plain cap, or it is a literal ordinary node whose EVERY row's selected child has the remaining corridor. A cap on the final projected value does not by itself certify every raw selected input on which EditRows may still execute a leaf. Do not invert normalization to invent those raw input caps.
