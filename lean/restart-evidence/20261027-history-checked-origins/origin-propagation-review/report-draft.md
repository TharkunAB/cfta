# Checked edge origins and projected arity

This is a source-only audit and proof draft. It does not establish arity for every recursive history. The current candidate is `drafts/v2/SourcePruningEnumerationArityOrigins.lean` (331 lines, SHA256 `e30011eca61a9e37e5adc81cd9050fa778bc860bd8d404b869158c65c15d72f7`). No compiler, build, test, Git command, network call, or repository write ran in this review. Root owns all checks and installation. The bundle remains open for Root's check receipts.

The minimal useful property is `Fits constraint arity`. It requires the existing fresh-arity gate for every successful projection and every starting ID. `Heap` applies this property to each actual stored canonical key and its key child count. This property depends on both the constraint and the child count. It is weaker than requiring the source `fits` Boolean on contradictory or nonprojectable constraints. `Heap.edge state heap coherent edge resident` converts key child count to actual payload child count through `Coherent.edges`.

The candidate derives `Heap` through actual raw construction. `Checked`, `ManyChecked`, and `EdgesChecked` constrain the original syntax. Each source edge must have `Fits` at its syntactic child count. `buildMany_length` proves that an actual successful child run returns that count. `buildEdges_heap` uses that equation before the actual raw `makeEdge`. `build_heap` covers nodes, unions, binder probes, canonical hits, pending entries, and actual callbacks. `constructed_heap` starts from the empty cache and the literal original build equation. These theorems preserve the existing raw runtime and its public admission.

The candidate also covers the copied-edge route. `encode_checked` and `encodeEdges_checked` derive checked syntax from actual resident edges. `InternedStoredSubstitution.encodeEdges` copies the original symbol and constraint and maps the child list one-for-one (lines 78–81). Coherent keys give the source child count. `encodeMany_length` gives the encoded count. `execute_heap` and `unfold_heap` then preserve `Heap` at the actual stopping cache, including pending results. They do not assert returned availability, Ready, language acceptance, or safe enumeration storage. Those facts remain separate existing receipts.

## Current invariant boundary

`SourceCurrentConjunctionEquality.FieldAvailable` is normalized equalities plus a successful physical load (20–24). Its `Fields` uses `SourceEqualityAnnotationHeap.Heap`, whose predicate receives only a guard (14–16). `SourceCurrentAllocatedNativePhysicalCompletion.Good` retains native validity, Ready, operation validity, and these fields (27–31). `Context`, `Inventory.At`, and `Recursive.Packet` do not retain checked creation of every stored edge. Their normalization and semantic facts do not provide this new numeric conclusion. This review does not infer endpoint arity from `Post` or `Keeps` alone. Growth retains old records and can also add new records.

Unrestricted raw closed syntax is insufficient as a checked-construction premise. `InternedNestedConstruction.EdgeSyntax.mk` accepts an arbitrary constraint and child list (24–26). `InternedFreshOrdinaryConstruction.buildEdges` calls raw `makeEdge` after its child computations (124–135). `makeEdge` interns the supplied key without a constructor arity test (`InternedConstructorTemplates`:228–231). `NativeConstructedHistory.query_complete` assumes this literal raw build plus original guard coverage and closed available operands; it does not assume checked syntax (24–43).

The exact obstruction is the raw source position `.node [.mk symbol constraint []]` for a constraint whose successful projection names a root child. The raw builder has no test at that position. The candidate therefore retains `Checked expression` explicitly. This is a source-domain observation and a counterexample recipe, not a checked full-Context countermodel or a Haskell runtime defect. Haskell `mkEdge` performs the missing rejection test (`Interned/Type.hs`:563–568). Its same-length `setChildren` branch relies on that original invariant (390–400). Source `fitsArity` checks the first path index against the child count (`Equality/Constraint.hs`:326–331).

The new candidate adapts this structure to child-count-dependent facts. It uses the actual `buildMany` equation where the guard-only proof did not need a length fact.

Do not copy the existing guard-only `CodeFields` continuation predicate as an arity proof. It quantifies over arbitrary continuation outputs. Accepted native construction needs the length of its actual child walk. Likewise, `NativeDemand.execute` on arbitrary user-supplied `.code (.work rawMakeEdge ...)` cannot derive projected arity from Ready. The next native preservation theorem must cover the actual generated node-query program and its creation receipts. It must retain actual caller, heap, full memo state, and reached control at intermediate steps.

The remaining global obligation is to produce checked original construction and then thread this derived property through every actual creation path. The current candidate closes raw checked syntax and copied-edge reconstruction. It does not yet close all native node queries, local reductions, narrowing, callbacks, or recursive history induction. Numeric arity, inherited trie validity, structural retention, and assignment meaning remain distinct obligations. No old semantic admission or whole-enumerator claim changes here.
